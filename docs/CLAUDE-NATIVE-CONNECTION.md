# 连接 Claude Code 终端

AgentKib 的终端连接和后台续接是两条独立路径。终端连接通过第一方 Mods 插件观察并按已验证能力控制用户已经启动的 Claude Code，不启动第二个 `--resume` 进程；空闲会话发送时可由 AgentKib 自动启动后台 CLI。每次启动或回收后重启都保留占用、身份、指纹、版本及权限校验，不再要求手工交接确认。

## 首次连接

本期原生连接限 macOS，最低 Claude Code **2.1.301**，插件合约版本为 **0.4.0**。CLI 使用最低稳定版本与显式能力检查，不再要求精确锁版。已完成原生验收的版本正常连接；更高但尚未验证的版本通过能力检查后同样允许连接，只在“连接终端”对话框显示中性提示“Claude Code {版本} 还没有验证过，同步显示可能不完整”，会话页不重复显示。放宽版本不保证所有未来版本兼容：从 AgentKib 发消息在每个版本上都经过同一套插件核对，结果无法确认时停用发送（见“发送和排队”）。Windows/Linux 不开放终端连接；组织策略、safe mode 或禁用 hooks 仍可能阻止插件加载。托管设置或 Team、Enterprise 登录会让 Claude Code 加载 sec-default，它跳过用户安装插件的 `classic.*` hooks（包括 PermissionRequest），插件本身照常加载，等待审批改由 `tool.check` 发现（见“能力和状态”）。

1. 在桌面打开所选 Claude 会话的“更多操作 → 连接终端…”。外部占用选择条目前不显示插件链接。
2. 按面板显示的路径添加本地 `agentkib-local` marketplace，主动安装并更新 `agentkib-bridge`。已安装时单独执行 `plugin install` 不会更新，因此指令还包含 `claude plugin update agentkib-bridge@agentkib-local`。AgentKib 不自动安装或修改个人配置。实测 CLI 2.1.311 从这个目录原地加载插件：AgentKib 更新后，新开的会话和 `/reload-plugins` 直接使用新代码；`plugin update` 更新安装记录，`claude plugin list` 随之显示新版本。
3. 已打开的终端执行 `/reload-plugins`。新建隔离测试会话也可用 `--plugin-dir` 加载随应用提供的插件目录。
4. 在 AgentKib 生成一次性连接指令，在对应终端执行 `/agentkib-connect …`。挑战只绑定所选 UUID 和工作区，120 秒有效，成功消费或断开后失效。

### 自动连接（默认开启）

插件装好后，在 AgentKib 已登记的工作区里开始或继续 Claude Code 对话，不需要连接码就会自动连上：

- AgentKib 运行时在 `<AgentKib 目录>/claude-bridge/auto-v1.json` 写入发现文件（权限 0600），内含本机 socket 路径和一个随 Runtime 每次启动更换的密钥。插件在会话开始时、以及每轮结束后（直到连上）读取它，依次查找 `AGENTKIB_HOME`、`~/.agentkib`、`~/.agentkib-dev`。
- 只用终端自己的会话 UUID 和工作目录配对。工作目录必须属于已登记的工作区，会话已被索引；新对话在第一轮结束、AgentKib 索引到它之后连上，最多重试 20 次。版本、能力和身份检查与连接码完全相同。
- 每个工作区都可以在“连接终端”对话框里关闭“自动连接这个工作区的新对话”；关闭的工作区只接受连接码。重新打开后，已开着的终端在下一轮结束后连上。
- 插件或 Claude Code 版本不符合要求时，终端的 `/agentkib-status` 和这条会话的“连接终端”对话框都会说明需要更新（用户断开过的会话和关闭了自动连接的工作区除外）。按第 1 步更新并执行 `/reload-plugins` 后，插件重新加载时会重新触发会话开始：工作区开着自动连接、也没被断开过的对话立即连上，不需要新的连接码，对话框里的更新提示也会这样写；其余对话仍按提示重新生成连接码。
- 在 AgentKib 里断开或清除过的会话会被记住，不再自动连接；之后要连接，仍需新的连接码。之前连过的会话照旧用保存的凭据重连。
- 已授权的手机能看到这些自动连上的对话，和用连接码连上的一样。

连接指引按“安装插件（只需一次）→ 生成连接码 → 在终端粘贴并回车”显示。生成后的长命令默认显示两行，点击可展开全文，复制始终包含完整命令；有效期只显示到分钟，小时不补零，和安全提醒合并显示，“重新生成”和“更多复制选项”放在第2步。“检查连接”只读取连接状态，保留尚未到期的命令。已连接和等待重连时，安装步骤收为可展开的“已安装插件”；过期时“重新生成”是主要按钮。各状态互斥显示，断开与清除在状态卡片内确认，焦点先落在“取消”，状态变化导致确认区重建时也保留安全焦点。不支持平台时只显示卡片中的平台原因，不再重复头部版本说明。macOS 的入口仅在“更多操作”菜单提供，不再在“会话操作”对话框中重复显示；Web 继续使用“电脑上的 AgentKib”操作说明，不提供安装或生成入口。

在线连接的“断开”需要确认，并说明终端照常运行、AgentKib 停止同步。终端退出或 AgentKib 重启后，已验证且尚未撤销的绑定独立于在线 lease 保留。连接终端对话框显示中性的“等待终端重新连接”，说明在终端继续原会话后会自动连接，无需新的连接码；不会跳回首次连接或要求重用已消费的连接命令。提供“复制继续命令”（使用经过身份与目录检查、正确引用工作目录和配置目录的现有 `claude --resume` 命令）、备用文字操作“重新生成连接码”和“清除连接…”。无法核实状态、来源失效、权限不足或结果未知时仍优先显示原有原因，不把保存过绑定当作已连接或允许发送。

“清除连接…”保留原地二次确认，撤销该终端连接的凭据与未使用连接码，不停止终端。收到明确成功回执后回到首次未连接指引；此后直接恢复终端会话不会再自动连接，必须重新生成连接码并主动连接。该操作复用原有断开权限与可撤销条件，不因离线而扩大能力。

“复制继续命令”与会话续接的其他同名入口共用经过目录、原生会话身份检查的生成器。默认配置只切换工作目录并执行 `claude --resume`，不主动设置 `CLAUDE_CONFIG_DIR`，避免改变 Claude Code 对用户级配置的选择；只有 AgentKib 自身环境显式设置了该变量时才在命令中保留。POSIX shell 与 Windows PowerShell 都引用完整路径和会话 ID，显式配置即使等于默认目录也保留。命令不复制凭据；粘贴终端自身的环境仍由用户管理。

复制安装、连接或继续命令后，成功提示保留 3 秒；切换会话、关闭面板、连接代际或状态变化（包括本地到期和结果待确认）立即清除。旧剪贴板回调和计时器不会把反馈带入新状态，命令内容和原有身份、目录校验不变

插件连接到 Runtime 的私有 Unix socket。应用数据中的绑定文件只允许当前用户读写；长期凭据不进入 Renderer、Web、URL 或日志。请勿把连接指令交给其他终端。连接和查看状态不发送模型请求。

### 版本与能力检查

- 兼容策略只有一处来源：`packages/claude-bridge-plugin/hooks/compatibility.js`。最低版本、插件合约及已验证版本清单由插件与 Runtime 共用，并随插件产物一起校验和打包。更新 `verifiedCliVersions` 前，先在 QA 保存该版本的原生只读同步验收证据；自动检查不会改清单、提交或发布。
- 每次连接和重连显式调用并检查身份、历史消息、上下文用量、插件自带文件读取及独立无敏感值的存储往返。命令注册、计时器已有实际调用，私有 HTTP 传输由真实握手验证。Mods 静态校验负责调用与事件注册契约；不能据此声称已经提前验证所有未来事件。事件、快照和身份仍逐次校验，缺口和未知结果仍保守处理。
- 后端在建立绑定或换发 lease 前，独立检查私有协议、插件合约、最低版本及完整的必需能力报告。CLI 升级后可以使用原凭据重连，但必须重新探测当前能力，公开状态与快照保留实际观测版本，不能伪报最低版本。
- 低于最低版本时提示更新 Claude Code；插件过旧或私有合约不匹配时提示按第 1 步重新安装；必需能力缺失时拒绝连接，提示继续在终端使用。无法识别的版本也拒绝连接，不从不可信字符串推断兼容。不兼容状态不显示连接命令。
- 已有绑定自动重连时，本地兼容失败也会显示在 `/agentkib-status`。插件只有重新读取并核对原会话身份、工作目录和保存的凭据后，才能向 AgentKib 上报具体原因；无法完成这些检查时只保留终端提示。诊断不建立连接、不换发 lease，也不覆盖已连接终端或正在使用的新连接码。桌面与 Web 复用四语提示，结果未知、设备权限和离线保护仍优先。
- 自动无登录检查由 `Claude terminal compatibility` 工作流每天 04:17 UTC 计划触发，也保留相关 PR 和手动触发。定时运行在工作流合入默认分支后生效，执行默认分支上的代码；本轮本机或 PR 验证不代表已经执行了每日计划。检查覆盖最低版和 registry 最新版的官方 CLI、严格插件验证、原生插件引擎中的合成 host 能力契约及桥接安全回归；失败摘要仅列出白名单能力名称，不输出原始错误或凭据。它不登录、不调用模型，不自动更新已验证清单或发布，并明确区别于真实 TUI 配对/模型验收。

## 能力和状态

| 界面状态 | 执行者 | 操作 |
| --- | --- | --- |
| 在终端中运行 · 已连接 | 已经运行的 Claude Code | 同步观察；空闲时直接发送，运行中可排到本轮之后或加入本轮（见“发送和排队”）；插件暂时不能接收消息时，输入区换成“在终端中继续这条会话，这里会同步显示”；停止在终端处理，跟随态不提供“停止”按钮 |
| 在 AgentKib 中运行 | AgentKib 自己管理的 CLI | 保留后台发送、审批、问答、附件及其他已验证能力 |
| 正在 Claude Code 中使用 | 外部会话无法连接 | 显示分支/返回选择条；返回后只说明在哪里继续，不提供续接命令 |
| 空闲（不显示状态） | 没有运行中的执行者 | 支持的主会话直接输入，发送前自动校验并启动 |
| 仅可查看 | 平台、版本或来源不支持继续 | 说明原因并提供当前客户端支持的替代入口 |

终端连接不显示停止终端及交接确认。连接失败且外部仍占用时不会另起同 UUID 进程；提供分支/返回选择，外部退出后重新核验，才能自动后台续接。

终端连接的**审批和问题仍在终端处理**，AgentKib 只显示等待原因。附件、上下文资源、目标、改名、分叉及设置不因连接成功而获得能力；队列只能添加和撤回，不能编辑、排序或暂停。工具过程复用摘要展示，不把历史工具记录当成可执行调用；没有原生报告的上下文用量显示暂无数据。

原生日志仍是完整历史来源。插件的近期快照及有界流缓冲不是完整导出；事件缺口会暂停控制并请求新快照，不伪造遗漏内容。隐藏推理不进入桥接消息。

插件在执行中重新加载时，可能尚未取得当前轮次 ID。此时界面保留“正在执行”，说明轮次尚未核实；这时不能加入本轮，排队的消息等终端确认空闲后再提交。曾触发审批但无法核实授权结果时，界面提示查看原终端，不把它表示为仍在等待审批。Claude 2.1.301 的运行中自动文件热加载在此前原生实验中未触发，不能保证立即恢复该轮流事件；空闲重载与故障注入测试分别记录。

等待审批有两个来源。`classic.PermissionRequest` 在 hook 链运行期间显示“正在等待工具审批”，之后转为“授权状态未核实”。sec-default 下这个 classic hook 不运行，插件改看 `tool.check`：主循环调用的结论为 `ask`、且由人回答（`approver` 不是 `host`）时，把该工具记为“授权状态未核实，请查看终端”，随该工具结束、出现进度提示或本轮结束清除。审批对话框何时被回答插件看不到，所以这里不显示为“正在等待”；子代理调用的审批在这种情况下不提示。插件只观察，`tool.check` 的结论原样返回。字段依据 2.1.311 内嵌的 Mods 类型声明，并在官方插件引擎（沙箱、无网络）中通过 `plugin validate --strict` 与 `plugin test`；没有 Team/Enterprise 账号，真实 sec-default 终端未验收。

## 发送和排队

插件合约 0.4.0 起，已连接的终端可以接收桌面、Web 和手机发来的文字消息。三种方式都要求插件确认连接可写；任何一次提交结果无法确认时，那条消息标为未知、不再重发；在重新配对或终端重新打开这条会话之前，插件不再接收消息。

- **直接发送**：终端已确认空闲、插件里也没有待处理的消息时，消息作为新一轮提交。原生 `$.prompt.submit` 没有原子的空闲门禁，所以由插件自己的 `prompt.submit` hook 把关：提交前会话有变化，或终端里先有人输入，这次提交作废，不会在终端里隐式排队。`turn.start` 报告这条消息开启的轮次后才算发送成功。
- **加入本轮**（steer）：本轮主循环正在执行工具时，消息立即用 `$.session.append` 追加，模型和工具结果一起读到；否则插件先保存，在本轮下一次主循环工具调用时追加。本轮没有再调用工具就结束时，这条消息在下一轮开头提交。指定的轮次已经结束才到达的请求按轮次冲突拒绝，不会改发到别的轮次。追加的消息在历史中显示为用户消息。
- **排到本轮之后**：插件按先后保存，本轮结束、终端确认空闲后逐条作为新一轮提交，错过轮次的“加入本轮”消息先发。终端先开始了别的轮次时，这条消息留在原位，等会话状态变化后再试，不会反复重试。

待处理消息最多 20 条，可以在队列里撤回尚未提交和结果未知的消息。终端会显示一行提示，说明 AgentKib 加入或排入了哪条消息。待处理消息只保存在插件内存中：插件重载、身份变化（`/clear`、`/resume`、`/branch`）或会话结束会丢弃它们，界面随新快照更新。

运行中发送的默认方式按设备分别设置，默认是排队：手机在“我的 → 偏好 → 运行中发送”，桌面在“设置 → 常规 → 界面”，Web 在“外观与语言”对话框。运行中点发送（桌面和 Web 也包括回车）按默认方式发出；手机长按发送、桌面和 Web 用发送旁的“…”菜单选另一种。这个默认方式同样用于 Codex 会话。

端到端依据见[终端发送方式 QA](../qa/claude-terminal-send-modes-2026-10-30.md)：真实 2.1.311 TUI，模型和 AgentKib 桥接都是本机模拟。

## 并发、重连和退出

- 桌面、Web 和手机复用同一 Runtime 连接和持久回执。“已连接”不代表此刻可以发送；可用的发送方式以插件当前快照为准，规则见“发送和排队”。
- 发送已接受与本轮已完成分别记录。失去确认后保留待核对，不自动重发；仅看到空闲状态不足以证明旧操作完成。
- 后台 CLI 的启动失败仅在用户消息尚未派发、且所属进程树已确认结束时恢复发送前状态，保留失败原因和草稿，回执记为“本次操作未执行”。清理依据先持久化，再发布可重试状态；重启恢复仍核对原生身份、记录代际、revision 和命令派发阶段。旧记录没有可验证清理依据、进程树清理不明、协议异常、已派发轮次或设置确认超时，继续保持结果未知；没有 runner 不能证明旧子进程已结束。
- 尚未派发的启动尝试在等待清理确认时，界面持续显示“正在启动…”，期间不能发送；内部未知状态和账本保护照常保留。只有确认安全恢复后才显示“本次操作未执行”，保留草稿并允许重试；无法确认清理或真实结果未知时仍显示未知。客户端等待自身发送回执期间，不把这条仍在处理中的请求提前当作失联回执核对。
- 启动清理证明使用 v2，记录本次从未启动进程，或通过 macOS owned-tree 清理确认的具体方式；缺少方式的旧 v1 不自动恢复。旧版或当前平台不支持的证明若已经恢复并保存 idle，仅在身份、代际和恢复 revision/turnId 精确匹配时隔离为结果未知；普通 idle 和已推进的后续轮次不回退。macOS 证明只在相同平台接受，监督范围沿用现有冻结捕获及内核进程身份校验，不声称追踪已脱离父链的任意 daemon。Linux 的原进程组清理仍保留，但不能据此证明已脱离进程组的后代全部结束；发送与显式设置准备在这种情况下保持结果未知，只有本次从未获得进程 PID 的失败可按未启动恢复。
- 安全隔离覆盖已释放后重新接入及同原生会话的索引别名；接入和 runner 每次实际重启前，都检查相同 HOME、工作目录和原生会话 ID 的其他托管记录。尚未确认的记录或占用中的记录锁会阻止继续，不通过新建托管记录或更换别名清除旧隔离。
- Linux 目前只能证明原进程组已清理，不能证明整个进程树已清理。实际启动后台 CLI 后发生启动失败（包括显式打开设置失败），会话保持“结果未知”，需要回到 Claude Code 继续；本轮不改变 Linux 清理逻辑。没有可验证清理证明的旧卡住记录也继续锁定，刷新不能解除该保护；桌面与 Web 提示改为返回 Claude Code 继续，不再引导“在主机核对后刷新”。
- 普通设置读取只使用已确认的主机缓存，不启动后台 CLI；用户显式打开设置时才通过独立的准备请求启动并读取原生选项。该请求保留设备权限、CSRF、原生身份、占用和 revision 检查，不提交设置或消息。空闲回收、离页或重连后不因设置刷新重新启动，缓存也不代表新进程的权限已确认。
- 显式准备完成或失败后，主机重新核实并发布权威终态，不让已结束的 starting 状态停留在界面。确认未派发且进程树已清理时可恢复空闲；外部占用、未知或清理不明继续阻止发送。重连会丢弃旧设置响应，但仍释放对应准备请求的忙碌状态，旧访问的请求不能清除新访问的忙碌状态。
- 内部取消链路及其测试保留，绑定原生轮次 ID、连接代际和 revision，不通过结束原终端实现。真实 2.1.301 插件能执行 `$.turn.abort`，但持续输出时界面 revision 可能在派发前过期，且完成回执存在不稳定观察；本轮按验收备选关闭跟随态停止入口，不削弱校验。AgentKib 后台 CLI 的停止功能不受影响。
- 插件重载、`/clear`、`/resume`、`/branch` 和身份变化会废止旧连接代际与表单。UUID 和工作区在命令派发前再次核对。
- 终端退出只结束当前在线 lease，未撤销的绑定仍保留。重新打开原会话时，插件读取保存的凭据，并重新核对身份、版本、能力和工作目录后连接，不需要复用旧连接码。AgentKib 重启后，保持打开的原终端使用既有后台计时器退避重试；用户下一次提交提示或开始主轮次也会唤醒检查，不等待重连再执行终端操作。服务持续离线时保持未连接，不重放旧消息或创建第二个终端进程。
- 自动恢复期间尝试备用配对时，不会另起后台重连，已经开始的旧握手回执按代际丢弃。新连接码过期或无效且未成功配对，不撤销仍有效的原绑定；多次重叠配对都失败后，仍可通过完整校验重新连接。明确撤销、身份变化或会话结束仍会停止旧绑定的恢复。
- 浏览器断线不停止本机执行。AgentKib 退出只关闭自己的桥接连接；原终端继续运行。再次启动后核对原操作，不回放旧命令。
- 桌面断开连接会同时撤销未消费的重连挑战，旧凭据不能恢复连接。

Web 仅能使用桌面已经建立且当前授权允许的连接，不能安装插件、生成连接码或提交本机路径。关闭会话索引、来源失效或撤销设备权限后，相关内容与控制按原权限边界失效。
