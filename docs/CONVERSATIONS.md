# 桌面与 Remote 实时会话

桌面的「会话」保留原目录、链接和历史分页。本机 Codex、Claude Code 和 Antigravity 会话可在原页面查看实时执行、输入消息、处理审批和问题。桌面与 `apps/web` 分别维护会话界面，共用 `packages/conversation-state` 状态逻辑及安全 Markdown 渲染；两端的生产组件分别接受相同行为的回归测试。其他只支持历史扫描的来源继续只读。平台、原生版本、执行归属和授权限制仍由主机返回，不根据 Agent 名称直接开放发送。

所有来源继续先加载最新记录，再按需补读更早页。正常分页不显示「轮次不完整」提示，也不将未读页标记为完整；真实读取错误、内容截断、保守工具折叠及滚动锚点仍保留。

桌面与 Web 打开或刷新会话时，历史读取完成即可显示正文，不等待实时状态和占用检查；控制区仍等待完整的权威状态与权限核验，历史可读不表示可以发送。Claude 原生旧会话的观察只做索引、工作区及记录头部身份校验，不为展示构造完整导出文档或计算控制指纹；发送和后台进程每次启动前的锁、指纹、版本、权限及新鲜占用检查保持不变。

同一会话、同一历史代次的重叠订阅共用进行中的快照读取，完成或失败后立即释放；每个订阅仍保有自己的游标与退出生命周期。Claude 实时观察在记录身份、文件版本与索引代次均未变化时复用历史投影，继续逐次查询实时状态，不缓存对外分页游标。追加、替换、身份失效、关闭或清空索引及显式历史失效会使投影失效；缓存按 32 条会话及 8 MiB 序列化内容限制，不用历史缓存作为控制证明。

桌面与 Web 的会话输入框使用 Enter 发送、Shift+Enter 换行，并在输入区显示提示。输入法组字期间的 Enter 不发送；发送不可用、附件上传或请求进行中时，快捷键沿用发送按钮的限制。steer 和加入队列继续使用各自的操作入口。

Claude Code 与 Codex 的同 Agent 续接直接使用会话输入框，不再提供“交给 AgentKib”“执行管理”或手工交接勾选。后台仍逐次核对占用、会话身份、工作区、指纹、权限、版本、原生状态及未知回执。没有后台进程时不显示运行徽标；AgentKib 的后台进程仍驻留时显示“在 AgentKib 中运行”，已连接的 Claude 终端显示“在终端中运行 · 已连接”。连接能力由主机返回，不能仅凭已连接状态开放发送；终端不能接收从这里发出的消息时，输入区换成“在终端中继续这条会话，这里会同步显示”。Claude 跟随态的发送与停止都在终端处理，不提供停止按钮；AgentKib 后台停止仍按已验证能力开放。首页、工作区概览和工作区侧栏的会话列表直接打开此页面；会话页“更多操作 → 在其他 Agent 中继续”在当前会话上直接打开原有跨 Agent 继续对话框；关闭或取消保留原会话与未发送草稿，生成计划后进入原变更计划流程。

会话正在别处使用且无法连接时显示「正在 {Agent} 中使用」及选择条，可以显式分支并继续，或返回该 Agent；返回后只说明在哪里继续，不提供续接命令。保留未发送草稿，定期重新检查占用。首页和侧栏不显示「正在 {Agent} 中使用」，打开会话后才确认。平台或版本不支持时显示「仅可查看」和具体原因。只读来源、校验中、未获授权、权限不足和未知结果分别说明，不因界面显示入口而启用控制；Web 保留复制续接命令与主机操作说明，不扩展跨 Agent 功能。

会话目录已不存在（例如 git 工作树已删除）时，Codex 与 Claude Code 会话的历史照常读取。Claude Code 的只读请求用最近一层仍存在的上级目录的真实路径拼上已删除的部分，再核对记录头部的会话身份和目录；该路径仍须位于登记工作区之内，经链接指到工作区外的照样拒绝，权限等其他读取错误照常报告。发送、接管和分支仍要求目录存在：两端输入区只可查看，并说明“会话目录已不存在，目前仅可查看。请恢复该目录后刷新重试。”Codex 使用原因 `codex-session-directory-missing`，Claude Code 使用不分工具的 `session-directory-missing`。会话页的工作树标签同时写“· 已删除”，不再另加一条删除提示。目录分组与工作树标记见[功能与兼容矩阵](FEATURES.md)。

显式分支一旦取得经过请求、来源和运行实例校验的完成回执，就在目录确认新会话可读后进入该会话；不等待新会话的历史加载完成才导航。原请求超时后只查询回执，确认同一次分支完成可恢复原导航意图，不重发分支。用户切换会话、访问身份或运行实例后，旧导航意图失效。

同一会话与授权绑定的后台巡检保留已核实的展示快照，避免选择条和终端观察态闪动；实际操作仍等待最新权限、状态和 revision 校验。切换会话、运行实例或授权时立即废止旧快照。目录只读查询遇到忙碌可有限重试，不向用户显示原始 `operation_busy`，不自动重发扫描或控制请求。其他会话的目录失效通知也会刷新列表，按核实的活动时间重新排序。发送中的本地用户消息按发送前历史锚点插入，实时回复始终排在它之后，原生用户记录到达后替换临时条目。

桌面创建会话后，保留新会话的输入区与订阅，直到外层路由和目录选中记录一致再结束创建状态，避免导航交接被当成离开页面而提前回收进程。创建或分支成功后的目录读取若遇到忙碌、真实错误或尚未包含新会话，保留待交接目标，在共享目录恢复或手动重试成功后完成导航，不重复创建或发送；改选、取消或离开页面会使旧交接失效。目录读取争用保留已核实的列表，等待目录或操作结束通知后重新读取；真正的读取失败仍保留错误及重试入口。Web 沿用其自身的会话路由，两端的控制授权与离页回收规则保持一致。

Codex 主流程只启动自己的 `codex app-server`，写锁最低版本为 `0.147.0`，实际续接由原生 writer lock 裁决；旧 follower 模块保留但不接入主路由。Claude managed 最低版本为 `2.1.263`，前台 Bash 契约为 `2.1.285`（CLI 帧处理验证到 `2.1.299`，更新版本不作门控），连接终端插件仍按其固定版本和能力门禁开放；Antigravity ACP server 为 `agy_acp_server_1.1.1`，且身份必须为 `antigravity-acp`。版本门槛不替代协议、归属、会话身份、revision 与审批关联校验，也不表示新版已完成真实环境验收；异常或溢出版本仍拒绝。两端分别说明安装未验证、协议不兼容、占用和连接失败，重新连接只恢复观察。

上下文指示器独立于设置能力，显示「最近原生报告」。Codex 使用 `last.totalTokens / modelContextWindow`，Claude 使用最新主会话 API 输入与缓存计数、配合同模型的原生窗口，ACP 使用 `usage_update.used / size`。累计消耗不作为当前占用，缺少有效窗口不推测模型容量，合法零值显示 `0%`。HTTP、SSE 基线与增量使用同一投影，并继续要求 full、advancedControl 及会话范围授权。用量报告代次独立于控制 revision；模型、owner、运行实例变化及断线会使旧比例失效，不启动任务或轮询聊天来取得新报告。

`Live.activity` 的 `compacting` 阶段与执行状态独立，显式 `null` 清除阶段。压缩期间两端和主机预检、实际派发均阻止发送、steer、设置、目标修改与执行归属转移；经原生确认的停止、审批问答和已支持的排队操作继续按各自条件开放。无 turn ID 的手动压缩不伪造停止目标。完成只清除压缩阶段，不强制转为空闲；断线和未知结果保护不会按超时解除。压缩开始使旧比例失效，只有可确认属于压缩后普通请求的报告恢复比例；否则结束等待动画并显示「用量待更新」，不继续锁住已恢复的发送能力。ACP 声明可选 compaction v1 Preview 能力，按原生 ID、终态及 replay 区分当前阶段；未发送此能力的 server 仍依赖既有执行锁，不能单独识别压缩。

完整控制入口包括附件、电脑文件与目录引用、模型与思考强度、Plan、策略、steer、队列、目标、管理操作、文件与产物。是否可用取决于当前原生链路。打开页面只建立观察，发送才自动启动续接；Claude 设置读取使用上次原生确认的缓存，只有用户显式打开设置或发送时才准备 CLI，普通刷新、重连和回收后的观察不会启动进程。Claude 每次启动或回收后重启前都检查外部占用，空闲约 10 分钟回收，或在最后订阅者离开且当前轮次结束后安全回收，运行中发现外部占用会停止自己的进程并提示。无后台进程时不显示运行状态；停留期间发生空闲回收只提示一次，重新进入不重播。Codex 一轮结束后空闲约 1 分钟释放自己的进程与锁；最后订阅者离开时，等待当前轮次完成后释放。未知结果、未决控制等保护不按超时解除。

Claude 后台启动失败时，只有确认用户消息未派发且完整进程树已结束，才返回“本次操作未执行”并恢复草稿和可发送状态，不自动重发。等待清理确认期间显示一致的“正在启动…”状态，内部未知保护不变。重启恢复要求与同一原生身份、记录代际和失败 revision 对应的持久清理依据；旧启动失败记录缺少依据时仍保留未知。已派发的轮次、设置确认超时、协议异常和清理不明继续阻断控制；旧卡住记录的提示说明可以回 Claude Code 继续，不再引导刷新解除保护。

Codex 闲置记录只剩 `.jsonl.zst` 时，目录会尝试读取压缩同名文件；会话身份验证读取有界前缀，历史分页和文档使用私有解压副本，全文索引按解压后的字节执行上限。副本命中和并发发布保持分页指纹稳定，不以缓存替代原生续接身份和写锁检查。

## 传输与恢复

本机原生事件由 TypeScript backend 托管的会话流投影并发送到 Electron `ConversationHub`，再分别进入桌面窄 IPC 与 Remote SSE。Runtime 协议版本为 17，会话协议为 2。Codex managed 会话直接转发 app-server 状态、文字增量与完成项；Antigravity ACP-managed 会话直接转发 ACP 状态与文字增量，并在回合结束后以原生 `session/load` 回放校正临时条目；Claude managed 会话直接转发 runner 状态、文字增量与完成项，并在原生消息 ID 到达后合并临时 ID。相邻文字增量最多合并 20 ms 或 32 KiB。其余只读会话来源以 250ms 有界快照核对作为更新来源。初始化、用户刷新、明确的历史失效事件及断线恢复也会读取基线。目录订阅仅收到摘要失效通知，不为每个目录条目启动完整会话连接。

快照只在事件读取器确认覆盖完整历史页时声明完整覆盖，并携带可验证的删除项及回合 ID；超过删除记录上限会递增历史缓存 epoch，要求清除旧分页缓存。非完整历史页保留其覆盖范围外已分页的记录。尚未接入逐来源 publisher 的会话继续依赖快照核对；快照轮询同时用于重新同步。

`sessions.subscribe` 返回基线或有界重放及游标，`sessions.event` 通知携带运行实例、epoch、序号与会话身份。游标独立于原生控制 revision。客户端只保存成功应用的游标；重复事件被忽略，缺口或失效游标触发重新同步。重放全部发送后用 `session-ready` 确认恢复，空重放也能恢复界面。重连只恢复观察，不重发发送、审批或管理命令。

恢复完成标记必须与此前发送的最后一个事件一致，包括重放期间到达的新事件。队列和管理回执在读取期间收到变化通知时，会在当前读取结束后再次核对；全局连接恢复也会核对未完成的管理回执。设置、目标及用量按对应原生变化更新，不等待回合结束。

空闲会话的原生 revision 推进时，也会校准设置与目标的读取版本；同批失效通知与在途变化合并读取，不因运行中的文本增量重复查询。已有编辑草稿保留，版本冲突仍要求重新载入，读取失败不自动循环重试。运行中的目标面板版本过期时，可显式重新载入；读取只更新投影，不自动提交或重发控制操作。

连续恢复失败达到上限才停止自动重同步；成功应用基线并收到匹配游标的 `session-ready` 后清零计数。游标过期导致基线替换时，一次核对队列、设置、目标、用量和能力，避免漏掉断线期间的变化。

有界原生快照通过 `preserveItemsOutsideCoverage` 区分缓存替换与消息撤回：只替换覆盖完整的回合，并删除明确列出的回合或消息身份，保留此前已经显示的较早记录。仅含最终回答的历史尾页不表示整个回合已完整读取。删除身份随重新订阅的基线保留；若其有界记录耗尽，`historyCacheEpoch` 改变，客户端清理旧缓存并重新读取历史，较早分页可重新加载。原生消息身份转换仍替换旧临时条目。目录通知在 SSE 写入积压时合并等待发送，恢复发送前重新检查授权。

保留的旧 Codex follower 模块仍有原生 owner、epoch、回执和有界缓存校验，相关测试不删除；D11 主路由不会调用它，续接失败也不会回退跟随。Antigravity 历史恢复若未收到匹配回执，会保持不可发送并关闭失效连接，避免剩余历史混入下一轮。

仅有回执而未观察到所需原生证据时继续保持结果未知，不重发命令。Claude 的文本条目使用记录 UUID，逐块增量完成后替换临时身份，同一 API 回复内的多个文本块仍分别保留并与历史合并。

Codex 的镜像历史记录跨分页保持同一消息身份，追加记录后重新分页也不会产生第二份回复。截断预览不声明整轮历史已完整覆盖，同一消息更完整且前缀一致的持久历史可替换预览。历史失效读取被后续原生条目或覆盖范围变化打断时，会保留最新原生内容并合并补读；连续变化只延后待执行的补读，不建立周期刷新。切换会话会取消补读，读取失败不会自动循环重试。

Codex managed 的增量和完成消息使用相同的实时文本上限，并按 UTF-8 边界裁剪及标记截断。完成事件不会用较短的持久摘要覆盖已显示的实时文本。持久历史中消息正文的格式和上限不变；工具条目另带有界的结构化详情，见「工具详情与轮次时长」。

Codex managed 恢复原生历史时，在响应所在位置一次发布有界且按原生顺序排列的基线，不将历史逐项重播为新回复；随后到达的原生通知再依次应用。两端按消息身份合并基线，保留已加载的较早分页和前缀一致的完整正文，历史恢复不触发「新消息」提示。managed 与 follower 共用原生条目分类及内容块文本提取规则。

Antigravity 已确认的完整历史恢复使用独立的有界完整投影，不先截成最近 100 项再替换。超过完整投影预算时保留当前内容并显示历史同步未完成；不把截断结果标为完整历史。

Runtime 使用独立 stdout writer；内存缓冲有界，不新增逐 token 持久日志。Electron 对早到事件和 SSE 积压分别限量，慢订阅关闭后重新同步，不阻塞原生 Agent。授权撤销、到期、Runtime 退出及工作区读取范围变化会结束对应观察；旧游标不能绕过新授权。

桌面 IPC 的基线、重放和持续推送共用消费窗口：每条订阅最多保留 256 个未确认事件、4 MiB 序列化内容。界面仅在 reducer 成功应用后累计确认游标；缺口或旧页面的响应不能释放当前窗口。超限后主进程发送一次小型重新同步通知，立即撤销该观察并停止推送，订阅名额保留至页面退订，原生任务不受影响。客户端重新读取基线，不重发控制命令。控制状态通知每个窗口最多一条在途，等待确认期间将后续变化合并为一次失效通知。

桌面聊天内的全局目录订阅同样确认已应用游标；发现缺口或重新同步通知时，撤销旧观察并重新取得基线。连续恢复失败有次数上限，达到上限显示错误并允许显式刷新重试；只有匹配游标的就绪通知才清零计数。旧连接尚未完成的授权或目录读取不能覆盖新连接的结果。

控制回执完成后的状态补发在对应原生状态锁内重新读取当前状态，不复用脱锁后的旧快照。账本保护解除仍会通知两端，即使原生 revision 没有变化；runner 替换后也不依赖旧实例的版本大小判断新状态。

重新订阅时，没有原生观察器的静态会话也会更新已验证的基线。例如安装受支持的 Claude CLI 后，原先的不可用状态可以恢复，不需要重启 Runtime。订阅已有原生观察器的会话仍从其受锁保护的当前状态取基线，不自动创建执行任务。

SSE 写入超时或积压超限时直接销毁连接，释放 socket、待写数据和订阅名额。局部状态事件沿用当前连接的 provider 与工作区权限，不因省略这些字段而重新开放控制；仅在重连重放不带基线时读取一次权限元数据，正常增量不查询会话快照。

取消观察立即停止本地推送；Runtime 忙导致退订失败时，Electron 保留去重的清理任务并串行退避重试，成功或原 Runtime 退出后清除。清理不会重建订阅或重放控制请求。

桌面 IPC 不开放任意 Runtime 方法或 HTTP 代理，只允许现有会话路由。桌面、内置 Remote 和 LAN 服务共用控制 admission、在途请求及未知结果保护。控制状态变化通过 `control-changed` 通知两端按需核对回执和状态，不改变原生流序号，也不轮询历史。原生命令账本仍负责持久化与恢复，页面重连和 idle 状态都不能清除未确认控制。

Claude 托管服务与原有 managed-resume 链路使用同一会话事件流。托管会话保留索引别名；创建、接管或释放归属后更换流 epoch，旧游标重新取得基线，重放已完成的管理请求不会再次切换归属。工作区 Claude 面板保留原有本地设备身份、附件和待确认请求存储，与会话页及 Remote 共用控制锁；已有未知回执不会因切换入口而被清除。

工作区 Claude 面板随执行状态触发的目录事件重新读取当前会话能力，生成结束后自动恢复可用的附件入口。能力读取与元数据刷新共用串行队列、会话身份校验及忙碌后的事件唤醒；普通文本增量不触发能力查询，能力更新也不要求重新读取正文历史。读取失败与实时连接失败分别保留保护：事件触发的补读成功会解除读取错误，空闲会话无需重连即可恢复输入和附件；元数据成功不会覆盖实时断线，普通流更新也不会清除尚未恢复的读取错误。完整读取失败时，下一次事件补读仍核对历史与执行状态，不能只靠元数据成功解除保护。

工作区 Claude 的目录订阅与详细会话订阅独立记录连接状态。目录短暂中断不会清除详细流的就绪状态，恢复到匹配游标后解除目录保护，并核对可能漏掉的回执通知；空重放同样恢复，普通文本更新不触发这项补读。目录恢复不会解除详细流断线、读取失败或未知回执保护，已退订连接的迟到回调也不能改变新连接状态。

完整控制核对期间，普通文本 revision 和用量更新不会触发重复读取；较新的普通字段按原生版本合并，执行归属、审批和控制保护等有效变化仍需重新核对。持续输出不要求等待原生事件暂停才能恢复控制入口。目录更新与完整刷新共享较新的授权结果，避免并发请求留下永久禁用的输入区。桌面目录读取失败会保留会话链接并显示重试入口，不把失败当作会话不存在。

切换会话不会丢弃尚未完成的全局目录更新；失效读取会在当前授权下重新核对，不恢复定时轮询。初次加载、历史更新及分页读取失败时，错误提示保留到历史读取成功；实时状态恢复本身不表示历史已经恢复。历史请求共享读取序号，旧失败不会覆盖新成功，旧成功也不会清除新失败；切换会话或缓存范围后，旧结果和错误不能影响当前读取。

目录移除会话或将其标为不可读时，清理对应的派生待处理提醒，旧实时流不能将其重新加入。仍可读会话的摘要暂缺待处理字段时，保留已有观察结果。未知命令回执独立保存，目录变化不会清除回执或解除控制保护。

目录读取遇到命令在途占用时，等待控制完成或后续目录事件再读，不把只读请求的忙碌状态当作当前会话的未知命令结果。完整刷新中的旧历史请求若已被同一范围内较新的成功读取覆盖，可以完成自身的控制核对；若缓存范围已替换，则仍持有控制核对权的刷新重新读取当前授权、历史和执行状态。仍未解决的命令回执、较新刷新和历史失败继续保留各自的保护；较新的主机控制状态不会被旧刷新响应覆盖。

完整刷新中的目录、历史或执行状态读取遇到临时占用时，也会等待控制完成、目录更新或重连事件后补读。完成通知先于忙碌响应返回时仍能恢复；再次占用则等待下一事件，不轮询或重发命令。并发只读校准的占用不会取消待恢复刷新，也不会让此前取得的 idle 状态提前开放控制；其他会话的命令结算同样可以唤醒恢复，迟到的忙碌响应通过新的只读校准恢复。恢复只属于原会话及原控制核对版本，切换会话、较新刷新、撤权或新出现的未知结果会使旧恢复失效；并发读取的真实失败仍正常报告。

忙碌后的历史补读保留已加载的较早记录及警告，并按历史页顺序插入工具结果；最新页首条为仅存在于历史中的工具结果，或最新页与已有内容没有交集，都不作为清空旧页的依据。分页覆盖只以实际读取的历史条目为依据，实时条目不能证明中间历史已完整读取。最新窗口与旧历史之间存在缺口时，「加载更早记录」优先逐页补齐缺口，接上后恢复旧分页入口；空扫描页仍沿游标继续。切换会话或缓存范围会取消旧分页的应用，原生删除记录及缓存范围重置仍负责清理失效内容。

普通刷新按实际保留的历史更新分页覆盖：保留已加载记录时继续使用原来的较早游标或已到开头状态；替换或清空历史窗口时同时重建覆盖，避免将已移除的记录当作补页终点。较新的分页请求先完成，不代表可以跳过这项核对。事件驱动的历史读取及恢复重试只将本次读取前登记且页面仍保留的历史视为已有基线；分页中残留的已删除身份和被完整回复取代的临时条目不算基线。首次读取或原生回滚移除了全部可见历史时，不相交的恢复页放到实时尾部之前；仍有历史保留时继续沿用已有的身份合并和最新页追加规则。迟到的完整刷新不能覆盖较新最新页的内容和游标。静态历史被外部重写或清空后，普通刷新仍可移除旧内容。

控制核对取得完整状态后替换旧控制字段，清除已失效的原因说明，同时保留消息、流式文本和传输游标；未解除的结果未知状态仍保持控制保护。

切换会话后，原会话未完成的刷新不能阻止新会话发送，也不能解除新会话的控制保护。结果未知状态按会话保留，返回原会话时仍需核对回执或明确刷新。索引重新启用后的目录通知会同时恢复目录内容与可用状态。

桌面在全部工作区扫描结束后重新读取统一目录，再校验会话链接。托管会话携带经过原生身份校验的索引别名，旧搜索链接自动定位到对应托管会话；「在其他 Agent 中继续」仍使用其原索引身份。首页和概览打开会话前只放宽会排除目标的视图筛选，并退出新建会话状态，不改变会话本身。工具栏显式刷新也会刷新当前聊天，后台目录扫描不会触发聊天历史重载。

两端在接近底部时跟随新输出；阅读较早记录时保留位置并显示「新消息」入口，点击返回最新内容。历史补页不计作新消息。加载同轮更早记录或追加实时工具时，通过共有条目保留过程分组身份，保持用户的展开或折叠选择及已有工具节点。

## 工具详情与轮次时长

本机 Codex 与 Claude Code 会话的工具条目（`tool-summary`）可带可选的 `tool` 详情，形状参照 ACP 工具调用：`kind`、`title`、`locations`、`content`，另有 MCP 名称、子代理动作和包装调用的子条目数（`children`）。`content` 只放有界预览：命令与输出末尾、文件的增删行数与缩短的统一 diff、MCP 参数与结果的文字。工具名、状态和耗时沿用 `tool_name`、`tool_status`、`duration_ms`；状态新增 `declined`，原生的 inProgress 记为 running。条目类型仍只有用户消息、Agent 消息和工具摘要三种。旧客户端忽略新字段，照旧显示工具名和状态；新客户端连接旧主机时没有详情，工具行保持原样；条目也没有正文时，工具对话框提示“这条记录没有可显示的详情”。

Codex 历史解析当前持久格式中的 `event_msg/item_completed`：命令、文件改动、MCP、网页搜索、子代理和图片查看各成一行；条目 ID 与某次调用一致时（MCP、子代理、等待）并入该调用的行。代码模式下 `exec` 产生的条目与调用 ID 不一致：同一轮中恰好只有一个尚未配对的调用时，该调用的子条目数加一；没有或有多个时不标父子，宁可多显示一行。消息仍取自 `response_item/message`，推理和计划条目不生成工具行；旧格式的 `exec_command_end`、`patch_apply_end` 照旧解析。Claude Code 历史由 `tool_use.input` 生成标题与类型，再合并 `toolUseResult`：Bash 取 stdout、stderr 的末尾，Edit、Write 由 `structuredPatch` 计数并生成预览，Read 只取路径与行数，不读取 `originalFile`。实时链路使用同一套归一化：Codex managed 处理 `item/completed` 与 `thread/read` 恢复，Agent 消息保留 app-server 给出的 `phase`；Claude managed 处理 `tool_use` 输入，并合并 stream-json user 帧里的 `tool_use_result`（2.1.311 真机确认带有），帧里没有时退回 `tool_result` 文本预览。托管 Codex 会话连接期间，历史就是这些实时条目，断开后改读原生记录。失败的 Codex 轮次以 Codex 的错误文字作为该轮最后一行（带 `cli_output`，按原样显示），实时取 `turn.error`，原生记录取 `task_complete.error`；Plan 回复里的 `<proposed_plan>` 标签在历史中去掉。

轮次时长取自 Codex `task_complete`、`turn_aborted` 的 `duration_ms`（托管会话连接期间取 app-server `turn/completed` 的 `durationMs`）和 Claude Code `system/turn_duration` 的 `durationMs`，以 `turn_meta` 记录：Codex 挂在该轮最后一个条目上，Claude Code 挂在该轮最后一条 Agent 回复上，该轮没有回复时不记录。Claude Code 以 stream-json 运行时会话记录里没有 `system/turn_duration`，AgentKib 托管的轮次改取 `result.duration_ms`：实时随该轮最后一条 Agent 回复下发，同时存进应用数据的执行账本，读取历史时补回，会话记录自带的用时优先（详见 [Claude Code 托管执行](CLAUDE-WEB.md)）。本期之前托管的轮次没有存下用时，仍不显示。

详情中的标题、命令、输出、diff 预览、MCP 参数与结果都按正文搜索与交接的规则脱敏，并隐藏 URL 中的敏感参数；增删行数在脱敏前计算，脱敏前的原始窗口按整行截取，不会把密钥截成两半。消息正文仍不脱敏。推理内容、Claude 的 `originalFile`、读取类工具的文件正文和图片字节都不下发。工作区内的路径显示为相对路径，家目录下显示为 `~/…`；路径只用于展示，浏览器提交路径的规则不变。单项上限集中在 `TOOL_DETAIL_LIMITS`：标题 512 字符，命令 2 KiB，输出末尾 4 KiB，单个文件的 diff 预览 8 KiB、合计 24 KiB，最多 20 个文件带预览、200 个文件计数，整个 `tool` 序列化后不超过 32 KiB；超出时依次去掉输出、文本和 diff 预览，保留标题与计数，并标记 `truncated`。历史页的 2 MiB 预算和游标缓存估算同时计入 `tool` 与 `turn_meta`，因此单页可能少于 50 条。只读授权的浏览器也能看到这些预览，与只读可看历史和文件的规则一致。

桌面会话页与 Web 共用 `@agentkib/session-ui` 的工具行。命令显示状态、非零退出码和耗时，展开后显示 `$ 命令` 与输出；文件改动显示 `+a -b`，展开后显示着色的 diff 预览；所有预览都按纯文本渲染。读取、搜索和网页只显示目标，不提供展开。失败的行默认展开。代码模式的包装调用记有子条目时隐藏，失败时保留，过程计数按可见行计算。有轮次时长时，该轮第一段过程的标题显示“用时 …”；一轮中有成功的文件改动时，回复下方按文件合并显示“已修改 N 个文件”，点击文件就地展开差异预览。桌面查看其他电脑上的会话仍使用原生桌面远程的只读视图，该通道会去掉新字段，只显示工具名和状态。Antigravity 等其他来源暂不提供详情；完整输出、完整 diff、撤销和进行中条目不在本轮范围。

## Claude Code 斜杠命令

Claude 托管会话的输入框在输入 `/` 时列出命令，来自 CLI 报告、随 capabilities 下发的命令目录，按设备过滤：桌面按这台电脑的用户处理，Web 按远程设备处理。菜单是 `@agentkib/session-ui` 的共享组件，名称和别名都可筛选，方向键选择，Tab 或 Enter 补全，Esc 关闭；输入框始终保留焦点，用 `aria-activedescendant` 指向当前选项。发送前按与后端相同的规则判断：AgentKib 有对应操作的命令（下一轮模型与思考强度、重命名、持续目标）带参数时直接执行，不带参数时打开对应界面；不能发送的命令保留草稿并说明原因。`/model` 接受不分大小写的别名或完整模型 ID，`/effort` 接受 low 到 max 五档；列表里没有的模型、其他级别或所选模型不支持的级别不改设置，保留草稿并说明原因。`/fast`、`/focus`、`/color` 在托管会话里不起作用，不列在菜单里。`/clear` 不出现在菜单里，需要空白上下文时新建会话；上下文用量对话框里的“压缩上下文”按钮单独发送 `/compact`，不动草稿，桌面工作区的 Claude 面板也有。会话记录里命令按输入显示，本地命令的输出显示为 Agent 回复，保留换行和 `<名称>` 这类占位。规则与原因码见 [Claude Code 托管执行](CLAUDE-WEB.md#斜杠命令)。
## Codex 斜杠命令
Codex 的 app-server 没有斜杠命令，`/compact` 这样的文字只会作为消息交给模型。Codex 托管会话的输入区输入 `/` 时列出 AgentKib 能代为执行的命令（压缩、审查改动、Plan、下一轮模型、权限与状态、重命名、目标、分支、结束后台终端、归档、文件改动、写 AGENTS.md），使用同一个共享菜单组件：带参数时直接执行，不带参数时打开对应界面，当前不可用时保留草稿并说明原因；追加指令和加入队列不执行命令，也不把它们作为文字发出。其余 Codex 终端命令不发送，说明只能在终端使用；其他 `/名称` 照常作为文字发送。规则只在客户端，主机不拦截。`/review [分支]` 和 `/init` 发出 AgentKib 写好的普通消息，和 Codex Desktop 一样不调用 `review/start`；`!命令` 暂不支持。命令表与原因见 [Codex 托管执行](CODEX-MANAGED.md#压缩后台终端与斜杠命令2026-10-28)。

## 附件与产物

桌面上传通过 IPC 传入有界字节，再进入与 Remote 相同的附件存储与校验。附件仍绑定设备、会话和内容版本；输入框移除或上传失败不会隐式发送。文件预览使用受控读取和带有效期的票据。HTML 在独立 loopback origin、无同源权限的沙箱中打开；不把本地文件路径或 HTML 注入主应用权限环境。桌面聊天不要求先开启 Remote HTTP 控制服务。

上传中取消会在 IPC 传输返回后，使用附件 ID 和版本清理暂存。开启 Relay 后，桌面产物仍使用本机隔离预览地址，Remote 使用中继预览地址；两者共享文件校验与票据授权规则。

同一面板的「网页预览」显示电脑上正在运行的网页：电脑端直接嵌入，远程浏览器经预览源代理，见 [网页预览](WEB-PREVIEW.md)。

桌面附件在读取文件内容前检查 25 MiB 上限，主进程接收后再次校验。桌面文件下载经已签发票据校验进入系统下载流程，不改变普通跨源导航限制。

发送前可预览本地 PNG、JPEG、WebP 和 GIF；SVG 与 HTML 不内联执行或预览。移除、成功发送及会话切换会释放本地预览 URL，发送结果未知时保留到回执核对完成，避免把不确定的发送当作成功清理。

## 版本组合

Remote 保留 `/api/web/v1` 路径；`info.protocolVersion` 保持读取协议 1，新增 `conversationProtocolVersion: 2` 声明实时协议，`access.protocolVersion` 返回会话协议 2。SSE 请求带 `protocolVersion=2`，控制请求带 `X-AgentKib-Protocol: 2`。旧客户端仍可握手、配对、读取历史和回执；其控制请求明确返回 `incompatible_protocol` 和 `controlOutcome: not-dispatched`，不向原生派发。新客户端连接旧主机时保留读取，只在确认实时协议 2 后发送对应协议头或开放实时与控制能力。Electron 与随应用打包的 Runtime 必须使用匹配的内部协议。

## 验证边界
