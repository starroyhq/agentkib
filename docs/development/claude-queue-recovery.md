# Claude 宿主队列暂停的界面接线

此状态显示在会话状态行，和项目 Agent 的「委派暂停」独立。桌面和 Web 使用同一份会话状态。

| 后台信号 | 状态词 | 原位操作 |
| --- | --- | --- |
| `live.schedule.paused` 为 `false` 或字段缺失 | 无 | 无 |
| `paused` 为 `true`，且 `requiresReconcile` 缺失 | 排队已暂停 | 「恢复」调用现有的 `queue-resume`。根据 `features["queue-resume"]` 控制可用性 |
| `paused` 为 `true`，且 `requiresReconcile` 为 `true` | 待核对 | 调用现有的 `reconcile` 核对原请求。核对证明旧写入方已退出后，按最新状态清除暂停或显示「恢复」 |

- 有自动续跑时间的用量限制继续用既有倒计时和续跑状态。后台会自动清理无因的调度暂停。
- 恢复的可用性以同一会话的最新能力和修订号为准。报告或目标可以让宿主队列暂停，即使待发区没有用户消息，也要显示状态。
- 核对只处理原回执。已派发且无法证明结果的输入保持原位「未确认」，不会再次发给模型。只有用户明确发起一条新消息才会重新发送。
- 授权变化和用户手动暂停继续保留。向用户显示短状态词，原始错误和内部原因码留在诊断。
