# 会话目录变化与送达路径

## 复现和边界

0.36.1 的全局目录流定期重读 AgentKib 的 SQLite 索引缓存。常规读取不会重新枚举原生来源。隔离环境向正在打开的 800 MiB Claude JSONL 追加 `custom-title` 后，12.08 秒内侧栏和页头均保持旧标题。手动刷新索引后 147 ms 读到新标题，证明现有标题解析能识别该记录。现场还有 70 多分钟没有索引尝试。会话记录尾读、会话流与目录索引的时机彼此独立。

原生变更按来源合批。Claude 普通 JSONL 变化只重读该文件的有界元数据窗口。Windows、Linux 和 macOS 都监听原生目录。macOS 共享 SQLite 来源另核对已知数据库和 sidecar 的文件版本，以覆盖目录监听漏报的 WAL 提交。共享来源每秒最多对账一次，按原生工作目录归入已登记的最深工作区。Codex 虚拟集合单独归属。已有全局目录流从缓存计算增量，客户端就地更新现有目录和打开会话的页头。

### #440 的影响

[#440](https://github.com/starroyhq/agentkib/pull/440) 的 0.5.13 插件在宿主声明读取原生转录时跳过快照的消息读取。会话流还能用同一连接中已见的轮次开始以及稳定的原生 `turn_duration` 证据恢复空闲显示。在 301 MiB 隔离桌面环境中，旧插件被人为阻塞 12 秒时，修复后界面在 164 ms 回到空闲，末条回复在 165 ms 显示。真正的发送权仍在 12.088 s 随插件确认恢复。两条路径分别处理结束显示和目录标题、活动元数据。旧插件无法立即确认真实状态时，目录由桥接实际状态继续保持其保守语义。

### 客户端和对账

- 当前 Web 以 `catalogPatch=2` 协商新增的目录行、删除、标题和归档。旧 Web 和手机在不理解扩展时依靠既有目录失效通知。桌面沿用本地 IPC 事件。远程只收到当前授权工作区内公开可见的行。
- 已读状态随读者授权投影。全局目录增量省略已读和交互私有信息。已读变更当前仍可触发作用域内的整目录对账，另一个设备的读回和回执顺序由已读路径处理。
- 首次加载、重连缺口、工作区或索引设置变化、来源覆盖不完整及大批变更继续整目录对账。复核读取失败沿用 `source-unavailable`、`source-partial` 等已登记理由和 #444 的重试分类。

## 60 秒负载验证

场景沿用 0.36.1 验收，打开侧栏和 800 MiB Claude 记录并让 5 个托管 Codex 并行写入。两个新测量窗口都执行 15 轮，最大并行数为 5。请求按桌面到后台的 `session.request` 操作统计。CPU 取同一后台进程的平均，停止写入后再记录 5 秒。

0.36.1 发布记录是 54 次整目录请求。原追踪没有调用栈，不能逐条归因。a 的带栈复跑也为 54 次，其中 29 次是会话 GET live 或 POST send 的权限查找，18 次是已读写入前后的权限查找，7 次来自托盘。新实现用单会话授权查找复用实时注册信息，并合并托盘和目录观察者的更新。

| 测量                     | #444 基线 |    本 PR |
| ------------------------ | --------: | -------: |
| 活跃窗口                 |  60.006 s | 60.011 s |
| 整目录请求               |        56 |        1 |
| 单会话授权查找           |         0 |       46 |
| 后台平均 CPU，写入中     |    10.37% |   10.55% |
| 后台平均 CPU，停止后 5 s |    14.34% |    6.13% |
| 停止后 5 s 的整目录请求  |         0 |        0 |

最后一次整目录读取来自托盘的 `readSessions`。单会话授权查找为 15 次 GET live、15 次 POST send 和 8 次已读的前后查找。首版在每 180 ms 处理共享数据库通知时，活跃 CPU 为 16.63%。限制为每个共享来源每秒处理一次后，活跃 CPU 接近基线。定稿的真实改名测量分别在 3.204 s 和 3.205 s 更新侧栏和页头，测量期间没有手动刷新。各 CPU 数值为同机隔离合成负载的单次测量。
