# 多 Agent 发现与历史阅读

验收结果见 [分层 QA](../../qa/MULTI-AGENT-HISTORY.md)。

## 找不到工作区时

在「设置 → 发现」查看来源诊断，确认实际扫描路径、扫描时间与失败原因。候选数不等于最终工作区数：同一路径可以来自多个 Agent，忽略规则也会影响纳入结果。未知数量显示为未知，不按零处理。

仅创建 `CLAUDE.md` 不表示 Agent 已把目录写入自己的会话索引。可将项目所在父目录加入扫描根目录，或手动添加工作区；无需创建模型对话来触发发现。检查配置的扫描深度以及项目是否已被忽略。

「支持发现」「支持会话列表」「支持历史阅读」是不同能力。安装了 Agent，不保证本机存在可读历史；缺少来源、格式不支持和读取失败应分别处理。旧运行时没有能力或诊断字段时，界面显示信息不可用，不推测支持情况。

## 只读来源

- OpenClaw：Agent 目录中的 `sessions/*.jsonl`，以及 `sessions.json` 提供的标题信息。
- Hermes：默认 Home 和各 profile 的 `state.db` 与 JSONL；同一 profile 的同一会话先合并、再过滤工作区，数据库元数据优先。双方目录冲突时以数据库归属为准；数据库不支持正文读取时仍可使用 JSONL 正文，不改变归属。一个来源失败不应抹除其他来源或已索引记录。
- Grok Build：`sessions` 和 `archived_sessions` 下的 `summary.json` 与 `chat_history.jsonl`；不展示 reasoning 记录。
- OpenCode：工作区发现合并 SQLite 和旧 JSON 来源；历史读取继续使用既有 CLI 路径。

会话归属使用可验证的目录信息，不根据标题猜测。历史正文按页有界读取；未知格式或预算限制不视为完整成功。OpenClaw、Hermes、Grok Build 的会话只可查看，不提供实时控制；能否交接给其他 Agent 按会话判断，见[会话互通](interoperability.md)。

OpenClaw、Hermes、Grok Build 将会话目录与已登记目录归一到项目根。同一根登记了多个目录时，会话只归属于一个代表：优先已登记的根目录，否则按目录深度、规范路径及工作区 ID 稳定选择，不受刷新顺序影响。这是项目根归属，而不是按会话 cwd 选择最近子目录。新增更优代表后，刷新会迁移已有缓存并保持会话 ID；子目录刷新只补充记录，只有代表目录的完整刷新才能删除缺席记录。迁移缓存本身不视为代表目录刷新成功。

Hermes SQLite 历史分页在剩余字节不足以显示一个 UTF-8 字符时，将整条未显示记录留到下一页（包括工具结果）。会话与消息时间均兼容整数／浮点秒、毫秒及 RFC 3339；浮点值按发现层规则转换，不接受非有限值或超范围值。

OpenClaw／Hermes 的 JSONL 工作区发现只检查前 256 KiB 内至多 32 条非空记录，不因会话文件总大小超限而跳过合法头部；预算内信息不足时保留预算提示。来源失败即使没有发现任何候选，也保留独立路径、状态和原因，不覆盖其他来源的结果。Hermes 数据库时间兼容浮点秒、整数秒／毫秒及 RFC 3339 文本。

工作区路径归一化后，来源证据另外保留原始 cwd 集合；同一工作区下的多个目录不互相覆盖。数据库升级使用增量迁移，旧记录没有这些证据时按未知处理。

## 权限边界

这些来源不新增远程授权。Web 和原生远程访问沿用已有配对及历史阅读权限；扫描诊断不额外向远程开放。查看历史不运行模型、不启动会话，也不发送审批决定。
