# 会话互通：方向、版本与验收边界

本页描述工作树中的实现，不代表已发布版本。统一中间格式仍是 `SessionDocument`；来源解析、目标转换、原生导入与 Web 托管控制分别判断能力。新目标目前为实验适配，不能将离线导入成功理解为真实模型续接已验收。

原生验收记录绑定各自的源码 revision、Agent 版本和产品界面。当前后端已迁移到 TypeScript；本轮执行器、恢复及 MCP 归属的自动化与候选包检查见[2026-10-07 稳定性 QA](../../qa/typescript-stability-2026-10-07.md)。历史 Rust Runtime、原生界面和真实回复记录仍保留原结论，不作为迁移后同方向已重新验收的证明。

### DeepSeek Harness 会话

DSH 的会话日志只追加：压缩时 DSH 写入摘要，并用一条摘要消息替换模型可见范围中被压缩的部分，原来的消息仍在日志里。插件读取 DSH 当前的模型可见范围（`sessionQuery.readSurface`），标出每条记录是否仍在其中。

- **默认交接：** 与 DSH 模型当前看到的一致，按可见范围中的顺序：每次压缩的摘要（以 `context-summary` 轮次保存，固定标注说明不是用户写的）在它替换的位置，排在压缩留下的回复和之后的消息之前；没有带上的记录数记为 `compacted-history`，需要确认。DSH 把较长的工具结果换成精简版本时，默认交接带精简版本。
- **可选带上完整历史：** 与 Claude Code 来源相同的“包含压缩前的历史”，按顺序带上日志中的每条消息，并在压缩点插入 `compaction-boundary` 标记轮次和该次摘要；工具结果用原始版本。DSH 的日志不会接不回，因此没有 `compaction-link-unavailable`。
- **不交接：** 推理内容、注入的上下文（AGENTS.md、技能、通知等）、系统与开发者消息，以及 DSH 自己运行的斜杠命令。用户消息中的图片从 DSH 读取后随文档带上（每份文档至多 32 张、共 32 MiB），读不到的记为 `external-attachment`。

### Claude Code 压缩会话

Claude Code 在手动或自动压缩时写入 `compact_boundary` 记录，并把压缩前的对话换成一条摘要。AgentKib 沿边界记录的 `logicalParentUuid` 把边界之前的历史接回来；该指针接不回时（例如指向边界之后写入的记录），改用边界里保留段的头部。候选及其父链只能使用该压缩边界之前已有的记录，边界之后出现的同名记录不能补足旧链。多次压缩逐段接回，环、悬空指针和重复 uuid 不会让回溯无法结束，也不会让同一条记录归属两段。

- **默认交接：** 与 Claude 当前看到的上下文一致，即最近一次压缩的摘要加压缩后的消息。摘要以 `context-summary` 轮次保存：角色仍是 user（各目标格式只有 user/assistant 两种角色），但正文以固定的 `[AgentKib: context summary …]` 标注开头，Markdown 里的标题是 `Context summary`，JSON 里带 `kind` 字段，因此不会被当成用户写的消息。
- **必须确认的损失：** 默认交接没有带上的压缩前时间线记录数记为 `compacted-history`；无法把边界接回更早历史（既没有可用的 `logicalParentUuid`，也没有可用的保留段头部、回溯途中缺失父记录，超过 1024 段，或所有历史候选累计超过 250,000 次节点查找）时另记 `compaction-link-unavailable`。默认摘要交接仍需确认这些损失；选择包含压缩前完整历史时，存在断链的来源不开放原生导入，即使确认损失也不能强行启动目标。用户可明确选择文件交接并确认不完整内容。
- **可选带上完整历史：** 交接对话框“高级选项”里的“包含压缩前的历史”（请求参数 `include_pre_compaction_history`，默认关闭，仅 Claude Code 与 DeepSeek Harness 来源显示）按时间顺序带上每一段历史，并在每个压缩点插入 `compaction-boundary` 标记轮次；此时不再记 `compacted-history`。文档会更大，仍受现有限制：来源读取 256 MiB、单行 4 MiB、交接内容 256 MiB 和历史预算窗口化。该选择随预览冻结：规划以及命令导入目标（OpenCode、Hermes、OpenClaw、Cursor IDE）的续接都按同一选择重读来源，选择不一致时来源指纹不符，操作被拒绝。
- **不变的情形：** 活动链没有跨过压缩边界的 Claude 会话、从未压缩的会话和其他 Agent 的来源，文档与原先逐字节相同，该选项被忽略。
- **同 UUID 重写：** 当前活动链使用同 UUID 的最新版本；回溯每次压缩时，使用该边界之前最近的版本（包括多次压缩间的中间版本）。已经输出的 UUID 仍可沿其旧版本继续追溯父链，但正文只归属最新采用它的段，不把重写副本当作新增轮次；不同 UUID 的相同正文仍保留。全文搜索沿用同一选择，旧的 Claude 正文缓存会重建。
- **摘要选择：** 优先使用该段父链中的摘要；回退仅接受所选边界记录之后、下一次关联压缩之前的直接子摘要，并按 UUID 使用该窗口内的最新版本。后来的重写不能替换旧段摘要，也不能补上旧段缺失的摘要；摘要同样遵循 sidechain 过滤。
- **未验证：** 目标 Agent 实际如何对待这条带标注的 user 消息，没有用真实模型验证。

Codex 原生导入要求 `codex --version` 输出的第一个 `X.Y.Z` 是 0.159.2 或更新的版本。写入的 `session_meta.cli_version` 固定为 `0.159.2`，与下文 Claude 记录的 `version` 同理，表示 AgentKib 输出的记录结构所对应的版本，而不是本机 CLI 的版本；Codex 会续接自己旧版本写下的会话，所以更新的版本照常导入（0.163.0 的复验见上表）。此外仍要求本机最新 rollout 的首条记录是带 ID 的 `session_meta`。导入的记录注明使用 Codex 内置的 `openai` 提供方；实测 0.163.0 恢复会话时沿用记录里的提供方，不随 `config.toml` 的 `model_provider` 改变，所以只配置了其他提供方的 Codex 继续对话时，请求仍按 `openai` 发出。

Claude Code 原生导入要求 `claude --version` 报告 2.1 或更新的版本：以后的版本不会因为版本号关闭原生导入，记录格式是否变化由下面的会话格式探针按本机实际写出的会话判断。此外还有三项只读校验，任何一项无法确认都会关闭原生导入、回退为交接文件，并在界面显示原因：

- **会话格式探针（`session-format-unverified`）：** 在 `projects/` 下所有项目目录里，只看 `<项目目录>/<UUID>.jsonl` 主会话文件（不含 `<UUID>/subagents/` 下的子代理文件，也不限于目标工作区），取最近修改的一个，读取开头最多 64 行 / 4 MiB。探针跳过所有不是 user/assistant 的元数据记录（不枚举类型，未知类型不会导致失败）和标为子代理（`isSidechain`）的记录，遇到含非空 `sessionId`、`uuid` 和 `message` 对象的 user/assistant 记录即通过。窗口内找不到这样的记录、文件为空或不可读、读到损坏或超长的行、记录结构不符，都判为未验证（失败即关闭）。`projects/` 下还没有任何主会话时不构成矛盾；最新的主会话若还只有元数据、没有消息（例如刚创建的新会话），原生导入会暂时关闭，该会话写入消息后恢复。
- **项目目录名（`project-directory-unverified`）：** 会话文件写入 `projects/<目录名>/`，目录名是工作区路径中字母和数字之外的每个字符（按 UTF-16 码元）替换成 `-`。该规则不在官方文档里，来自对已发布二进制的公开解读，对齐的是当前版本的 CLI；公开 issue 报告较早的版本会保留路径中的空格（只替换路径分隔符），而版本门限不区分它们。编码后超过 200 个字符时 Claude Code 会截断并追加未公开的哈希，同时设置 `CLAUDE_CONFIG_DIR` 与 `CLAUDE_CODE_PROJECT_DIR_NAME` 时目录名由 CLI 另行决定，AgentKib 都无法确定目录，因此拒绝原生导入。
- **配置目录（`config-directory-invalid`）：** 会话文件写入 `CLAUDE_CONFIG_DIR` 所指目录下的 `projects/`，未设置时为 `~/.claude/projects/`（官方：该变量覆盖配置目录，`projects/` 在其下）。AgentKib 只认自己进程环境里的该变量，值不经 shell 处理，`~` 与 `$HOME` 不会被展开。空值和全空白按未设置处理；其他不合法的值（相对路径、含 `..`、文件系统根目录、含控制字符或首尾空白、超过 4096 个字符，以及 Windows 上的 UNC、设备路径和不带分隔符的盘符路径）会关闭原生导入，界面状态为“不可用”，改正环境变量后即可恢复。已生成的预览在应用和启动时按同一规则复核，不合法时拒绝写入。

这三项规则的自动化测试只使用手工构造的合成会话。2026-10-14 用真实 Claude Code 2.1.299（Haiku 5.5，一次调用）另做了验收：用 AgentKib 后端把手工构造的来源会话导入为原生会话，目标工作区目录名同时含 `.`、`_` 和空格；在该目录下 `claude -p --resume <UUID>` 找到了这份会话，并答对了来源会话里的暗号，没有因 `version: 2.1.233` 报错。只验证了这一个 CLI 版本和这一种目录名组合，详见 `qa/claude-live-acceptance-2026-10-14.md`。2026-11-09 又在 Claude Code 2.1.319 上复验，没有调用真实模型：AgentKib 后端把合成的来源会话（含工具调用与结果和图片）导入隔离的配置目录，工作区目录名含空格和 `.`；`claude -p --resume <UUID>` 找到这份会话，发给本机模拟接口的请求包含导入的全部内容，详见 `qa/native-import-version-gate-2026-11-09.md`。

写入后、启动 `claude --resume` 前，AgentKib 还会对刚写入的文件做一次结构性往返校验，任何一项不符都会中止启动（不打开终端）：每行是合法 JSON 对象；记录类型只限 `user`、`assistant` 与收尾的 `last-prompt`；`uuid` 不重复，首条消息的 `parentUuid` 为空、其后每条指向前一条，`last-prompt.leafUuid` 指向最后一条消息；每条记录的 `sessionId` 等于文件名与启动请求；消息的 `cwd` 等于目标工作区；文件位于该工作区按上述规则算出的 `projects/<目录名>/` 中；文件开头通过上面的会话格式探针。该校验是结构性的：不启动 Claude，本身不能证明 `claude --resume` 一定找到这份会话（上面的两次验收只覆盖 2.1.299 与 2.1.319）。写入记录的 `version` 字段固定为 `2.1.233`，表示 AgentKib 实际输出的记录结构所对应的 Claude Code 版本，而不是本机检测到的 CLI 版本。

Cursor IDE 本机连接需要在会话页选择“连接 Cursor 窗口”，检查随应用打包的 VSIX 并手动安装到选定 profile，再在目标单文件夹窗口运行 `AgentKib: Connect This Workspace` 并输入限时挑战。AgentKib 不自动安装扩展，也不猜测默认 profile；多个窗口须显式选择。连接恢复沿用原 binding，CLI 与 Agents Window 保持独立能力边界。

因此，来源与目标表面必须分别验收；代表性解析、离线导入、原生 UI、Runtime 重启及真实回复不能互相替代。缺少已配置模型、授权或运行环境时保留未验收状态，不自动登录或迁移凭据。Windows/Linux 自动化不代替实机验收。

## 审查、失败与恢复

文件写入目标仍沿用既有 ChangeSet。命令导入目标在 Changes 中展示应用数据目录内的 `plan.json`，其中包括冻结并脱敏的来源文档、目标投影、载荷、版本/存储身份及操作指纹。它是**准备文件**；批准后才会调用目标 CLI，目标内部数据写入不伪装成 JSONL 文件 diff。

OpenCode/Hermes/OpenClaw 的历史工具调用转换为标注的历史文本，工具参数/原始输出与附件可能省略；预览明确显示损失。转换器不保留可再次执行的历史工具调用。必要用户/助手正文发生未知变化时拒绝导入。新目标不支持尚未经验证的 AgentKib 长历史检索；超出完整窗口时不静默截断。

MCP 连接可以使用唯一注册 ID，旧 manifest URL 仅兼容唯一归属。归档与操作文件仍保留原 manifest namespace；多个已注册 clone/worktree 共享该 namespace，或它与其他注册 ID 冲突时，拒绝归档读取、长历史写入及歧义操作恢复，拒绝发生在 write/import 前。普通 registered MCP 访问不受该归档限制；Hub 每次归档读取都重新核对归属。重新写连接 URL 不迁移或重新分配旧归档。

每次明确分叉有独立操作 ID；开始外部导入前先写入持久化尝试标记。重复 RPC 复用记录；导入后必须核验归属、正文、角色及已知结构，失败不得启动模型。Hermes 出现父/子会话关联可能被官方恢复流程重定向，目前保守拒绝自动恢复；OpenCode 已撤销的历史同样拒绝。CLI 非事务导入发生超时、断流、退出或部分写入时，保留现场并显示待核对；不会因响应丢失再次导入，也不会自动降级为文件交接。会话页可查看持久化记录并核对/恢复已有目标。无法确认安全删除时不自动清理目标对象。

OpenClaw 使用固定版本自带的写入函数维护原生索引与投影，写入期间持有官方状态锁。已有 Gateway 或本地 TUI 占用时拒绝导入及自动恢复，不停止用户进程。目标数据库必须已是已验证版本，AgentKib 不自动迁移旧存储。启动仅打开已核对的本地会话，不发送初始提示；正文、身份、工作区或代际改变时拒绝恢复。

当前 TypeScript 后台执行器串行处理，允许 1 个执行中请求和 8 个等待请求；总期限从入队起计算，默认 180 秒，排队满时立即拒绝。耗时历史读取、哈希和序列化在只读 Worker 中处理，普通 Runtime 请求继续响应。退出时拒绝待执行请求并取消外部等待，已启动的本地写入执行至结束或自身回滚。已开始且结果不明的导入保留尝试记录，只允许核对，不自动重放；Cursor 导入失败后还会重新从原绑定的存储核对。任务失败不自动创建替代目标。不承诺目标 CLI 的跨进程事务、强杀或断电恢复。

上下文文件交接仍可由用户明确选择，它创建引用文件，不计入原生互通验收；DeepSeek Harness 目标只用这种方式，由 AgentKib 新建 DSH 会话读取该文件。这些互通适配不授予 Web 控制权限，也不自动迁移 Agent 配置或凭据。
