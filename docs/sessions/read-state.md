# 跨端阅读状态

每个会话保留最新的未读结果，包括完成、失败、取消和无法可靠分类的“已结束”。Codex 原生手动标记未读也使用同一阅读状态。会话再次运行时，上轮未读继续保留为运行行上的圆点。已读只移动阅读游标，不删除会话、结果或审批记录。

桌面目录不再常驻“待查看”卡片：普通列表保留未读圆点，点击铃铛在原项目列表内筛选待查看会话，包括仍在运行的未读会话，再次点击恢复原列表。筛选与现有 Agent、电脑和记录筛选叠加；筛选期间展开结果项目，退出后保留原折叠选择。阅读确认后该行移出筛选结果，正在阅读的会话保持打开。审批、提问和待核对操作仍使用原待处理中心及计数，在会话窗口有实际待处理事项时显示入口。

只有当前会话在前台、未被弹层遮挡、最新结果已成功加载且实际显示在阅读区域中时，客户端才确认已读。从“待查看”进入会定位到结果；普通进入保留原阅读位置。没有正文的失败或取消显示结束标记；没有结果的原生手动未读会话需要显示新鲜的空会话界面。后台刷新、加载失败、旧位置恢复和缓存恢复不能产生阅读确认。

## 状态来源

Codex 原生 `readState` 可用时，以其为唯一权威；在原生 App 中阅读或手动标记未读会同步到 AgentKib。电脑端复用按规范化原生目录隔离的只读 app-server 连接，读取原生轮次和回执，不恢复会话或取得执行权。通知用于加速失效，前台观察期间每五秒调度有界轮询，覆盖目录候选及已知未读。

明确不支持原生回执的 Codex 会话和 Claude 会话使用电脑端私有 SQLite ledger，并显示“仅在 AgentKib 内同步”。临时错误保留上次状态并标为待同步，不触发降级、不冒充已读。Codex 恢复原生能力后重新以原生回执为准。Claude 原生终端内的查看不会被承诺为 AgentKib 已读。

补充结果和游标使用 `codex-managed/executions.sqlite` 中独立的 `conversation_read_*` 表，不写入业务命令回执。键由 Agent、规范化原生目录和原生会话生成，阅读身份由电脑所属账号或独立模式的本机用户推导；托管和导入别名共享记录。首次可信历史扫描建立已读基线，此后的明确结束结果持续保留到确认。扫描失败不建立空基线，检查点和新结果一并持久化，重启后补齐遗漏。断线、idle 和运行标记消失不作为结束证据。

手机和浏览器只缓存投影，云账号与中继服务不保存阅读状态。退出、切换账号或电脑时隔离缓存与迟到响应。

## 接口

现有配对和会话范围校验继续生效。只读设备可以确认阅读，无需发送、高级控制或实验功能权限；POST 仍要求准确 Origin 和 CSRF。`access.readStateVersion: 1` 声明接口能力，目录会话中可选的 `readState` 缺失代表旧电脑不支持，不能解释为已读。

`GET /api/web/v1/read-state?sessionId=…` 返回 `{readState}`。

`POST /api/web/v1/read-state` 接受：

```json
{ "sessionId": "会话 ID", "expectedVersion": "实际展示过的不透明版本", "seenResultId": "结果 ID" }
```

仅无结果的原生手动未读允许 `seenResultId: null`。状态包含 `source`（`codex-native` / `agentkib`）、`status`（`read` / `unread` / `unknown`）、`freshness`（`current` / `stale`）、不透明 `version`、`firstUnread` 位置和 `latestResult`。结果包含 ID、原生轮次/条目定位信息、结束时间和 `completed` / `failed` / `cancelled` / `ended` 分类。版本只允许相等比较，不能作为时间排序依据。

原生确认使用 `expectedRevision`，补充游标通过 SQLite 事务比较更新。旧确认不能清除新结果或新的手动未读。冲突（`409 read_state_conflict`）或结果不明时，只 GET 读回；不自动重复 POST。需要新的进入、主动查看或刷新动作以及重新展示的新版本才能再次确认。确认不进入审批计数、发送保护或业务 pending。

桌面的旧配对电脑 TLS 通道使用同等语义的 `read-state` / `read-state-update`，由接收电脑推导独立模式身份，复用已配对证书、注册会话范围和撤销校验。

## 验证与发布

先更新电脑端，再更新 Flutter 和网页客户端。新客户端连接旧电脑时提示升级，保留原有历史读取和审批能力。新增私有表由新电脑端按需创建，旧版程序不读取这些表；回退版本不会删除记录，但不提供此次阅读同步能力。

自动化回归覆盖状态分类、基线、检查点、重启、别名、版本冲突、未知结果、身份切换、可见性及四语言布局。真实原生双进程验收运行：

```sh
pnpm --filter @agentkib/desktop verify:codex:read-state /绝对路径/codex
```

此脚本使用临时 Codex 数据目录、离线 Responses 夹具和两个独立 app-server 进程，验证结束未读、双向确认、手动未读、目录投影和迟到 CAS；macOS 下限制网络仅访问本地夹具。缺少原生可执行程序或验证失败会返回非零。`--keep` 保留合成数据供原生界面验收，不接触真实会话。

发布验收还必须在隔离的 Codex 原生 App 中打开合成会话，观察手机、桌面和网页同步移除，并反向确认。双进程、类型生成或模拟回调不能替代这项界面验收；环境限制应单独记录为未验证。
