# AgentKib Claude Code session bridge

First-party local Mods plugin for Claude Code **2.1.301 or later**, using AgentKib
bridge contract **0.3.0**. It connects AgentKib's existing chat interface to the
terminal's original execution process. It never starts a replacement Claude
process, resumes another UUID, calls a model itself, or changes the user's
permission rules.

## Connect a session

Use AgentKib's connection panel for the selected session. Register the bundled
`agentkib-local` marketplace and install `agentkib-bridge@agentkib-local` using the
commands displayed there. In an existing terminal, run `/reload-plugins` to load
the plugin, then execute the one-time `/agentkib-connect …` command generated by
AgentKib. For isolated development only, `claude --plugin-dir <this-directory>`
loads the plugin for that invocation without installing it.

### Automatic connection

Once the plugin is installed, sessions in a workspace registered in AgentKib
connect without a code. While its broker runs, Backend writes
`<AgentKib home>/claude-bridge/auto-v1.json` with mode 0600, holding the socket
path and a key that rotates with every Runtime start. At session start, and after
each turn until it succeeds, the plugin reads that file (`AGENTKIB_HOME`, then
`~/.agentkib`, then `~/.agentkib-dev`) and calls `/v1/auto-pair` with its own native
identity. AgentKib pairs the session only when its working directory belongs to a
registered workspace whose automatic connection is on (the default; it can be
switched off per workspace in the connection dialog), the session is indexed,
and the user has not disconnected it. A disconnect is remembered, so that session
connects again only with a new one-time code. A workspace switched off keeps its
open terminals retrying, so they connect on their next turn once it is switched
back on. A saved binding still reconnects with its own credential. The same
version, capability and identity checks apply as for a code; when they fail,
`/agentkib-status` explains why. Updating the plugin and running `/reload-plugins`
starts the session hooks again, so the session connects without a new code.

Only the native session UUID and working directory selected in AgentKib can pair.
Each pairing and reconnect checks the minimum stable CLI version and required
native capabilities: session identity, messages, usage, credential storage, and
plugin-file reads. Older or unrecognized versions and missing required capabilities
are rejected. Only **2.1.301** is currently listed as verified; higher stable
versions that pass these checks may connect read-only. The connection dialog shows
a neutral notice that the version has not been verified and synchronized content
may be incomplete; the session page does not repeat it. Production sending remains disabled. `/agentkib-status` is a local
command and does not call a model.

## Current capabilities

- Read bounded native messages, tool activity, stream text and reported usage.
- Production text sending is **experimental-disabled**. Native `$.prompt.submit`
  has no atomic idle/CAS contract and skips this plugin's own hook by re-entry;
  a competing terminal submission cannot be guaranteed never to queue. The
  retained correlation implementation is an isolated protocol experiment only.
  Renderer, Web and plugin configuration cannot enable it.
- Cancel the exact native turn observed by `turn.start` using `$.turn.abort`.
- Keep approvals and questions in the original terminal. No permission override,
  synthetic question response, or remote approval capability is provided.

Snapshots are previews of the latest 80 text rows and 100 tool records, subject to
a byte budget. Clipped text has an explicit marker. Complete history continues to
use AgentKib's original history provider. Hidden thinking is never forwarded.

Native cancellation and reading are verified separately from experimental send
correlation. Approval and question completion remain unavailable in AgentKib.
A bounded event buffer retains turn-completion evidence until ACK, including
across reconnect; an unknown send is never unlocked merely because the TUI is idle.

The connection uses HTTP over a private local Unix socket. Persistent credentials
are written by Backend with mode 0600. The plugin reads that file through the
native API; its store keeps only the credential file path. Tokens do not enter
commands, URLs, or the chat UI. Native identity changes and session end invalidate
the lease; Runtime owns persistent request receipts and unknown outcome recovery.

A saved, unrevoked binding survives terminal exit and AgentKib restart. While
offline, the desktop connection dialog shows a neutral waiting state with a
quoted resume command, a fallback to generate a new code, and inline-confirmed
clearing. Clearing revokes both the saved binding and unused codes; resuming the
terminal afterward cannot restore that connection without explicit pairing.
Recoverable transport failures are retried using the existing Mods timer and
terminal events, with identity, version, capabilities and credentials checked
again. Retry never replays a send or creates a replacement terminal process.
An expired or invalid fallback pairing code does not revoke an existing valid
binding or permanently cancel its recovery, including after overlapping failed
pairing attempts. No additional background recovery starts while pairing is
pending; stale handshake responses cannot affect the current generation. Explicit
revocation, identity changes and session end still prevent that binding from
reconnecting.

## Validation

The `Claude terminal compatibility` workflow checks the minimum and latest CLI
daily at 04:17 UTC, on related pull requests, or when manually triggered. Scheduled
runs use the default branch and start after the workflow is merged there; local
or PR validation does not prove the daily trigger has run. Failures report only
known capability names. Checks do not sign in, call a model, change the verified
version list, or publish a release.

```sh
claude plugin validate ./packages/claude-bridge-plugin --strict
claude plugin test ./packages/claude-bridge-plugin
pnpm --filter @agentkib/desktop exec vitest run test/claude-bridge-plugin.test.ts
```

The official plugin tests need no sign-in, network or model. An optional macOS
integration test starts the installed TUI in an isolated config directory and
uses a synthetic localhost provider with no real credentials:

```sh
AGENTKIB_CLAUDE_BRIDGE_NATIVE=1 \
  pnpm --filter @agentkib/desktop exec vitest run test/claude-bridge-native.test.ts
```

Set `AGENTKIB_CLAUDE_EXECUTABLE` when the installed binary is elsewhere, and
`AGENTKIB_NATIVE_BRIDGE_EVIDENCE_DIR` to retain redacted terminal output and the
binary/type identity. For the separate send-correlation experiment only, set
`AGENTKIB_CLAUDE_BRIDGE_SEND_EXPERIMENT=1` on this test command: the test changes
one literal in its temporary plugin copy, never the shipped plugin. Passing
that experiment does not open production send capability. This verifies transport and native execution contracts;
it does not substitute for real provider or physical phone acceptance.
