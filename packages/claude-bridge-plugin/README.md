# AgentKib Claude Code session bridge

First-party local Mods plugin for Claude Code **2.1.301 or later**, using AgentKib
bridge plugin **0.5.11**. It connects AgentKib's existing chat interface to the
terminal's original execution process. It never starts a replacement Claude
process, resumes another UUID, calls a model itself, or changes the user's
permission rules.

When AgentKib and the bridge negotiate `terminal-handover`, the bridge can
request native exit for a confirmed takeover. It waits for the identified turn
to stop before invoking the built-in `exit` command. AgentKib independently
checks ownership before continuing the same session. Queued terminal messages
and claimed reports stay with the terminal until delivered.

The plugin and the Runtime need not come from the same AgentKib release: within
protocol 1 the Runtime takes this contract and any later one, and a terminal that
still runs an older plugin after an AgentKib update keeps connecting.

## Connect a session

AgentKib installs `agentkib-bridge@agentkib-local` at user scope when it detects
Claude Code. You can turn off automatic installation in Agents & Integrations.
Use the connection panel for the selected session. In a terminal opened before
installation or an update, run `/reload-plugins` or reopen the session. An unchanged
hooks module may remain alive. Sessions eligible for
automatic connection need no code. For an explicit connection, execute the one-time
`/agentkib-connect …` command generated by AgentKib. For isolated development only,
`claude --plugin-dir <this-directory>`
loads the plugin for that invocation without installing it.

### Update the plugin

AgentKib verifies the user-scope install before removing old project and local
entries through Claude Code. Migration keeps plugin data and leaves versioned
caches in place. Subsequent automatic updates target user scope. AgentKib leaves
a marketplace with the same name and a different source intact.

Settings and the connection panel show the installed scopes and failure details.
Manual installation commands are only shown following an automatic install failure.

You can also turn on Claude Code's own auto-update for `agentkib-local` from
the Marketplaces tab in `/plugin`. [Claude Code plugin updates](https://code.claude.com/docs/en/plugins/install#keep-plugins-updated)

Claude Code may load a cached copy, which it keeps when the version stays the
same. Rebuilding in another directory leaves the registered source unchanged.
[Cached plugin updates](https://code.claude.com/docs/en/plugins/loading#versions-and-updates)

### Automatic connection

Once the plugin is installed, sessions in a workspace registered in AgentKib
connect without a code. While its broker runs, Backend writes
`<AgentKib home>/claude-bridge/auto-v1.json` with mode 0600, holding the socket
path and a key that rotates with every Runtime start. At session start, after each
turn, and while disconnected with a 1/2/4/8/16/30-second backoff, the plugin reads
that file (`AGENTKIB_HOME`, then
`~/.agentkib`, then `~/.agentkib-dev`) and calls `/v1/auto-pair` with its own native
identity. AgentKib pairs the session only when its working directory belongs to a
registered workspace whose automatic connection is on (the default; it can be
switched off per workspace in the connection dialog), the session is indexed,
and the user has not disconnected it. A disconnect is remembered, so that session
connects again only with a new one-time code. A workspace switched off keeps its
open terminals retrying, so they can connect while idle once it is switched back
on. Retries continue at the capped interval, including when AgentKib starts after
the terminal. A saved binding still reconnects with its own credential. The same
version, capability and identity checks apply as for a code; when they fail,
`/agentkib-status` explains why and AgentKib shows the same reason in that
session's connection dialog. A native session that has not finished binding its
history API is retried without accepting a connection before the full capability
check succeeds.

Only the native session UUID and workspace selected in AgentKib can pair.
The bridge uses Claude's session root as the workspace identity. Shell commands
can change directory within that workspace without breaking the connection.
Paths outside the workspace, including symlinked subdirectories, are not used
for bridge control. A native move to another checkout still requires its own
workspace validation.
Each pairing and reconnect checks the minimum stable CLI version and required
native capabilities: session identity, messages, usage, credential storage, and
plugin-file reads. Older or unrecognized versions and missing required capabilities
are rejected. Only **2.1.301** and **2.1.310** are currently listed as verified; higher stable
versions that pass these checks may connect too. The connection dialog shows
a neutral notice that the version has not been verified and synchronized content
may be incomplete; the session page does not repeat it. Messages sent from AgentKib
go through the same plugin checks on every version. `/agentkib-status` is a local
command and does not call a model.

## Current capabilities

- When the Runtime names the `lead-tools` feature and AgentKib makes the session a
  Project Agent, register its worker tools (`mcp__agentkib-bridge__worker_*`) with
  `$.tool.register` and run their calls through AgentKib. Submit each report once the
  terminal is idle. With `lead-report-acks`, the plugin stores each report's
  ID before submitting it. A bridge prompt and its matching native turn confirm
  delivery, even if the call to submit the prompt lost its result. After a
  reload, the report's ID in the native user message and its following assistant
  message can recover the receipt. With `lead-report-message-ids`, the plugin
  also sends the UUID stamped by the engine on its user message, so AgentKib can
  display the structured delivery on that history entry. An unconfirmed native submission remains
  available for reconciliation, and later reports can proceed. Older Runtimes
  still use the intake acknowledgment before submitting a report. While the session leads,
  the tools run without asking: the plugin answers the engine's default ask for them
  with allow, and leaves any rule, hook, setting, other plugin's or organization's ask
  or deny as it is. Turns no one typed (a background task's notice, a schedule) carry
  no `origin`, so AgentKib counts them toward the Project Agent's automatic turns, and
  a line in the terminal says when delegation pauses or resumes. See
  `docs/agents/project-agent.md`.

- If Claude Code ends the Project Agent's main turn with a `rate_limit`
  `StopFailure`, the plugin locally pauses taking reports from AgentKib and
  submitting reports already in the outbox. This gives Claude Code time to
  continue the task itself. The plugin can resume after a native
  quota-resume notification, a normal turn completion, or a prompt the person
  enters in the terminal. The fallback uses the latest reset of a full window
  reported by Claude Code, plus 30–90 seconds. With no usable reset it tries
  once after five minutes. Another rate-limit failure then waits for a native
  resume signal, a normal turn completion, or terminal input. When the Runtime
  advertises `lead-rate-limit-pause`, the plugin tells it whether reports are
  paused. Older Runtimes still work with the local pause. Claude Code's failure
  event covers rate limiting generally and supplies no reset time for this
  turn. Where Claude Code policy suppresses classic hooks, the plugin cannot
  detect the rate-limit failure. [Claude Code hooks](https://code.claude.com/docs/en/hooks#stopfailure)

- Register `worker_restart` when AgentKib offers it alongside the other Project
  Agent tools.

- Read bounded native messages, tool activity, stream text and reported usage.
- On an idle, connected terminal that lists its built-in `/model` command, open the native
  picker on request. Press `s` in Claude Code to apply the selection to this session. The
  receipt confirms dispatch to the picker. Read the selected model through the optional
  native getter after the terminal reports it. Other settings remain
  read-only; history may supply a previous model or context count, never a
  fabricated current permission mode, capacity or writable choice. Compaction
  temporarily withholds previous context counts. The workspace browser uses the
  host's existing file grants and cannot attach references to terminal messages.
- On a writable connection that negotiates `terminal-attachments`, take desktop
  and Web attachments as Markdown links to copies in the native session's
  workspace. The Mods prompt API submits text, so images use the same links.
  Claude Code reads the linked file under its own permission rules.
- Take user messages sent from AgentKib, in three modes. Each needs a verified,
  writable lease. After any outcome the plugin cannot confirm, that message is
  marked unknown and never sent again, and the plugin takes no more messages
  until it is paired again or the session is reopened in the terminal.
  - **Send** while the terminal is verified idle and nothing waits in the outbox,
    with `$.prompt.submit` as the user. Native submit has no atomic idle/CAS
    option, so this plugin's own `prompt.submit` hook admits the prompt only while
    the session is unchanged and drops it when a terminal prompt entered first;
    it never queues in the terminal. A send is accepted once `turn.start` reports
    the turn it opened.
  - **Steer** into the running turn. While a main-loop tool runs, the message is
    appended with `$.session.append` and the model reads it with the tool's
    result. Otherwise the plugin holds it and appends it at the turn's next
    main-loop `tool.call`; if the turn ends first, it opens the next turn. A steer
    that arrives after its turn ended is refused as `turn-conflict`.
  - **Queue** for after the running turn. Messages wait in order and each is
    submitted as its own turn once the terminal is verified idle; steers that
    missed their turn go first. A dispatch dropped because the terminal moved
    first is tried again only after the session changes.

  The outbox holds up to 20 messages and lists them in snapshots. A message the
  terminal has not taken, or one of unknown outcome, can be withdrawn with
  `cancel`. The terminal shows a line for each message AgentKib adds or queues.
  The outbox lives in plugin memory: a plugin reload, an identity change or the
  end of the session discards it.

- Cancel the exact native turn observed by `turn.start` using `$.turn.abort`.
- Keep approvals and questions in the original terminal. Apart from a Project
  Agent's own worker tools above, no permission override, synthetic question response,
  or remote approval capability is provided.
- With the Runtime's optional `terminal-approval-observation` feature, include a
  bounded preview of an identifiable terminal approval and a short question summary.
  The plugin correlates a main-thread tool call and its unchanged human `ask` verdict
  with the native permission-prompt notification. Claude Code emits this notification
  after roughly six seconds of waiting. Ambiguous calls omit the approval preview.
  Inputs with recognized credentials are redacted, and no new approval action is exposed.
  [Claude Code notification hooks](https://code.claude.com/docs/en/hooks#notification)

Snapshots are previews of the latest 80 text rows and 100 tool records, subject to
a byte budget. Clipped text has an explicit marker. Complete history continues to
use AgentKib's original history provider. Hidden thinking is never forwarded.

When the Runtime offers `terminal-worker-activity`, version 0.5.5 can report
foreground work for a Project Agent's Worker. The main turn's tool call hook
provides opaque call IDs and start times until each call returns or fails. A
counter records arriving text, thinking, and tool transitions without including
thinking content. This observation starts with the next complete turn if the
plugin loads mid-turn. Attached tools are observable for the duration of their
call. Detached background commands have no lifetime signal here.

Approval and question completion remain unavailable in AgentKib.
A bounded event buffer retains turn-completion evidence until ACK, including
across reconnect; an unknown send is never unlocked merely because the TUI is idle.

The connection uses HTTP over a private local Unix socket. Persistent credentials
are written by Backend with mode 0600. The plugin reads that file through the
native API; its store keeps only the credential file path. Tokens do not enter
commands, URLs, or the chat UI. Native identity changes and session end invalidate
the lease; Runtime owns persistent request receipts and unknown outcome recovery.

A saved, unrevoked binding survives terminal exit and AgentKib restart. While
offline, the desktop connection dialog shows a neutral waiting state with a
quoted resume command, a fallback to generate a new code, and inline-confirmed
clearing. Clearing revokes both the saved binding and unused codes; resuming the
terminal afterward cannot restore that connection without explicit pairing.
Recoverable transport failures are retried using the existing Mods timer and
terminal events, with identity, version, capabilities and credentials checked
again. Retry never replays a send or creates a replacement terminal process.
An expired or invalid fallback pairing code does not revoke an existing valid
binding or permanently cancel its recovery, including after overlapping failed
pairing attempts. No additional background recovery starts while pairing is
pending; stale handshake responses cannot affect the current generation. Explicit
revocation, identity changes and session end still prevent that binding from
reconnecting.

## Validation

The `Claude terminal compatibility` workflow checks the minimum and latest CLI
daily at 04:17 UTC, on related pull requests, or when manually triggered. Scheduled
runs use the default branch and start after the workflow is merged there; local
or PR validation does not prove the daily trigger has run. Failures report only
known capability names. Checks do not sign in, call a model, change the verified
version list, or publish a release.

```sh
claude plugin validate ./packages/claude-bridge-plugin --strict
claude plugin test ./packages/claude-bridge-plugin
pnpm --filter @agentkib/desktop exec vitest run test/claude-bridge-plugin.test.ts
```

The official plugin tests need no sign-in, network or model. An optional macOS
integration test starts the installed TUI in an isolated config directory and
uses a synthetic localhost provider with no real credentials:

```sh
AGENTKIB_CLAUDE_BRIDGE_NATIVE=1 \
  pnpm --filter @agentkib/desktop exec vitest run test/claude-bridge-native.test.ts
```

To test the session-only model chooser on Claude Code 2.1.323, run:

```sh
AGENTKIB_CLAUDE_BRIDGE_NATIVE_PICKER=1 \
  pnpm --filter @agentkib/desktop exec vitest run test/claude-bridge-native.test.ts
```

This starts a fresh terminal and Runtime, opens the built-in chooser through the bridge,
selects Haiku for that session, and checks that the Runtime reads Haiku while the fixture's
global model remains Sonnet.

Set `AGENTKIB_CLAUDE_EXECUTABLE` when the installed binary is elsewhere, and
`AGENTKIB_NATIVE_BRIDGE_EVIDENCE_DIR` to retain redacted terminal output and the
binary/type identity. This verifies transport and native execution contracts;
it does not substitute for real provider or physical phone acceptance.
