# Claude Code 终端连接：排队发送和加入本轮

日期：2026-10-30。分支 `feat/claude-terminal-send-modes`，基于 `fix/model-options-cache`。

## 范围

已连接终端的 Claude Code 会话可以从桌面、Web 和手机发文字消息：终端空闲时直接发送；运行中可以排到本轮之后，或加入本轮。各设备分别设置运行中发送的默认方式。插件合约从 0.3.1 升到 0.4.0，旧插件连接时会提示更新。

## 改动

- 插件 `hooks/register.js`：
  - 运行中发来的消息放在插件内存里的待处理列表（outbox），最多 20 条，随快照上报。
  - 加入本轮：主循环工具执行中直接 `$.session.append`；否则先保存，在本轮下一次主循环 `tool.call` 执行前追加；本轮先结束则在下一轮开头提交。轮次已结束才到达的请求按 `turn-conflict` 拒绝。
  - 排到本轮之后：终端确认空闲后逐条 `$.prompt.submit`，与直接发送共用 `prompt.submit` hook 的核对；被丢弃的提交等会话相对提交时有了变化再试（终端抢先跑的那一轮就算变化）。
  - 撤回：尚未提交或结果未知的消息可以撤回。
  - 直接发送在生产中开放，去掉 `SEND_CONTRACT_EXPERIMENT`，并要求待处理列表为空。结果无法确认时标为未知；在重新配对或终端重新打开这条会话之前，插件不再接收消息。
  - 终端里用一行提示说明 AgentKib 加入或排入了哪条消息。
- 协议与后端：新增 `ClaudeBridgeOutboxItem`、快照 `outbox`、能力 `steer`/`queue` 和命令 `steer`/`queue`/`cancel`；`live` 增加 `steerEnabled`、`queueEnabled`、`queueEditEnabled`、`queuedCount`；`capabilities` 按状态开放 `steer`、`queue-add`、`queue-delete`、`queue-list`，`queue-list` 沿用托管队列的返回形状。
- Web 服务：终端连接的会话允许 steer、queue-add、queue-delete。
- 历史：插件追加的消息（`isMeta`，origin 为 `agentkib-bridge`，只有文字）显示为用户消息。
- 桌面与 Web：新增“运行中发送”，默认排队，保存在本机。桌面在“设置 → 常规 → 界面”（嵌入的会话界面不显示“外观与语言”对话框），Web 在“外观与语言”对话框。运行中点发送或回车按默认方式发出，发送旁的“…”菜单保留两种。
- 手机：“我的 → 偏好 → 运行中发送”。运行中点发送按默认方式发出，长按发送列出两种；发送按钮有长按动作时，提示气泡不再响应长按。
- 默认方式对所有支持加入本轮和排队的会话生效，包括 Codex 会话：以前运行中按回车不发送、点发送弹出菜单，现在按默认方式直接发出。

## 端到端检查

真实 Claude Code 2.1.311 TUI，HOME、XDG 目录和 `CLAUDE_CONFIG_DIR` 都指向临时目录。模型是本机合成的 SSE 服务，AgentKib 桥接用私有 Unix socket 上的模拟服务按插件协议下发命令。插件从工作树复制，经 `/agentkib-connect` 配对。脚本和结果在 `/tmp/akb-sm-e2e/`（`run.mjs`、`result.json`、`transcript.jsonl`），没有提交到仓库。

| 场景 | 做法 | 结果 |
| --- | --- | --- |
| A 空闲直接发送 | 终端空闲时 send | accepted，带本轮 turnId；模型收到这条消息 |
| B 加入本轮，工具调用前 | 模型用 5 秒写工具调用，期间 steer | accepted，turnId 为当前轮；消息先留在待处理列表；工具执行时追加，工具结果之后那次模型请求里有这条消息，仍在同一轮；终端有提示 |
| C 加入本轮，本轮不再调用工具 | 最后的回答流式输出时 steer | 本轮结束后这条消息开启下一轮，待处理列表清空 |
| D 排两条、撤回一条 | 工具轮进行中 queue 两条，再撤回第二条 | 撤回前列出两条，撤回后一条，撤回时本轮仍在运行；第一条在本轮结束后作为新一轮执行，第二条没有执行；终端有提示 |

会话记录里，加入本轮的那行是 `isMeta: true`，origin 为 `{kind: "plugin", name: "agentkib-bridge"}`；直接发送和排队的消息是带 `asUser` 的普通用户行。

前几次运行有检查项失败，原因都在脚本：工具结果之后的请求归错了类，几项检查取值太早。只修正脚本后重跑，全部通过。下面的插件修正之后又跑了一次，结果相同。

## 复查中修正的问题

排队的消息正要提交时，如果终端里有人先发了一条，插件的提交会被丢弃，这是预期的；但它记下的是丢弃时的 revision，而终端那一轮已经让 revision 变过了，于是这条消息要等到再有一轮开始或结束才会提交，终端一直空闲时就一直不发。改为记下提交时的 revision：会话在这期间变过就在终端空闲后立即重试；被其他 hook 拒绝、会话没变时，仍然等会话变化，不会反复重试。

用插件测试的夹具写了一次性测试模拟这个时序：修正前失败，修正后通过；“会话没变不重试”的情况修正前后都通过。

主机侧也用 broker 测试的夹具写了一次性测试，通过真实的 `ClaudeBridge` 和 Unix socket 走一遍：加入本轮、排队、列出队列、撤回都得到 accepted，会话没有进入“结果未知”，轮次结束后可以直接发送；指定的轮次不是当前轮时以 `stale-turn` 拒绝且不下发命令；有待处理消息时不开放直接发送。两组一次性测试验证后已删除，没有提交。
