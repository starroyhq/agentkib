# 回复里的文件引用：识别、按会话目录解析、手机点开
日期：2026-10-30。主机分支 `feat/file-references`，基于 `main`（`68102fcb7`）。手机端在 agentkib-flutter 的 `feat/file-links` 分支，只在本机提交。
## 范围
会话回复里提到的文件，主机能识别更多写法，并按会话的工作目录解析相对路径。新增按单个引用解析的接口，手机点回复里的文件时用它找到文件并打开预览。
## 改动
- 识别（`markdown-links.ts`）：
  - 除了 Markdown 链接的本地目标，行内代码里像文件路径的文字也算候选。带 `/` 的要有扩展名或 `Makefile`、`LICENSE` 这类常见文件名；不带 `/` 的只认常见扩展名，`console.log`、`res.json` 这类代码写法除外。网址、带空格或 shell 符号的文字、隐藏目录和 `node_modules` 下的路径不算。链接文字里的行内代码以链接目标为准，不单独算。围栏代码块里的内容仍然不收。
  - 去掉行列号后缀（`:12`、`:12:3`、`:12-20`、`#L12`、`#L12C3-L20`）和开头的 `./`；`file://` 地址转成本机路径；其他协议和页内锚点不算。
- 解析（`artifacts.ts` 的 `resolveReferences`）：
  - 新参数 `directory`，即会话的工作目录。相对路径先按它找，再按工作区根目录找。工作目录在根目录之外，或在主机不提供预览的目录里（如 `.worktrees/` 下的工作树），相对路径不解析，免得显示另一份检出里的同名文件；绝对路径照常解析。
  - 百分号编码的目标（`with%20space.txt`）也试解码后的路径。
  - 授权规则不变：仍在授权根目录内逐个校验，隐藏文件、敏感文件名、符号链接和多硬链接文件都不提供。
- 后端：新的只读操作 `session-directory`，从会话索引或 Codex 托管账本读工作目录；Claude 托管会话在工作区根目录运行，返回 null。不启动任何进程，也不校验原生会话。
- Web 服务：
  - `GET artifacts` 改用新的识别规则。一页的候选先去重再截到 100 个，以前超过 100 个时整页返回 413；结果按文件去重。
  - 新接口 `GET artifacts/resolve?workspaceId=…&sessionId=…&reference=…`，授权与 `artifacts` 相同（文件权限，会话属于该工作区），返回 `{artifact}`，找不到或不允许读取时为 null。旧主机对这个路径返回 404 `not_found`，手机据此提示更新电脑端。
  - 本机桌面通道（`isConversationPath`）和运行时路由加了这条路径和操作。
  - 读不到会话工作目录时按工作区根目录解析，与以前一致。
- 文档：`docs/REMOTE-CODEX-WEB.md` 的会话产物说明和接口表。
## 手机端
- 电脑允许本设备读取文件时，回复里的 Markdown 本地链接和像路径的行内代码可以点。点开后向主机解析：找到就打开预览；找不到、权限已被收回、主机太旧时各有提示。链接文字里的行内代码不单独成链接，以外层链接为准。
- PDF、Office 文档等应用内不能显示的文件，以及 CSV/TSV，多了“打开文件”：下载到临时目录后交给系统，iOS 用 Quick Look，Android 交给其他应用（`open_filex` 5.0.0）。临时副本在离开预览页时删除。Markdown、HTML、图片和音视频仍用应用内预览；HTML 不交给系统，保留隔离预览。
- 超过主机 1 MiB 文本上限的文本文件，以前提示“超过移动端 64 MiB 下载上限”，现在说明是文本显示上限，可以打开、保存或分享；超过 64 MiB 的仍提示下载上限。
- Android：去掉 `open_filex` 声明的存储和媒体读取权限（应用只打开自己缓存里的副本，不需要权限）；它的 FileProvider 只暴露应用缓存目录，不再包括外部存储和设备根目录。
## 验证
- 一次性测试（验证后删除，没有提交）：
  - 识别：行列号和 `./`、`file://`、尖括号目标的整理；网址、协议、锚点被排除；54 个像路径和不像路径的例子；顺序、去重、围栏代码块和链接文字里的行内代码。
  - 解析：子目录会话先找子目录再找根目录；`../` 在根目录内可以，越出根目录不行；工作目录是根目录或未知时按根目录；隐藏工作树和根目录之外的会话不解析相对路径，绝对路径照常；隐藏文件即使写绝对路径也不提供；百分号解码。
  - HTTP：没有文件权限 403，会话不属于工作区 403，缺少 `reference` 400；带行号、`./`、`#L` 和 `file://` 的引用都能解析；会话目录读不到时按根目录；引用超过 100 个的一页返回 200 而不是 413；`artifacts` 结果按文件去重。
  - 后端：索引会话读到索引里的目录；托管记录读到账本里的目录；没有目录的返回 null；多余字段被拒绝。
  - 手机：Markdown 解析出的链接地址（空格、中文、`%20`、`#L12`、`file://`、Windows 盘符）都能还原成引用；点行内代码链接和 Markdown 链接都交给打开流程，没有处理函数时不变成链接，设备没有文件权限时消息里没有文件链接；打开流程的成功、找不到、旧主机、其他错误和没有文件权限五种情况；大文本卡片和三个按钮，下载后写出临时文件；超过 64 MiB 的大文本仍显示下载上限；PDF 和 CSV 有“打开文件”，代码文件没有。测试环境调不到 iOS 和 Android 的系统打开，这一步只能在真机上看。
- 既有测试：桌面 `electron/main` 全部和 11 个涉及后端 Web 读取的测试文件，1304 项通过，1 项按条件跳过。手机 `flutter analyze` 无问题，`flutter test` 683 项通过，1 项跳过；其中“没有内嵌预览的文件”一项按新增的“打开文件”按钮更新了预期。
- 类型检查：backend、desktop、web 通过。格式检查通过；oxlint 没有错误，只有既有的警告。
- 手机构建：iOS release 构建通过。Android debug APK 构建通过；合并后的清单里 `open_filex` 的四个权限标为已移除，剩下的权限都来自已有依赖（网络、相机、视频播放的 `WAKE_LOCK`、androidx.core 的动态接收器权限）；APK 里的 `filepaths.xml` 只有 `cache-path`。
## 未覆盖
- 桌面和 Web 界面的回复里，文件引用还不能点；只有手机端可以。
- 只写文件名的引用（如 `app.py`）只在会话工作目录和根目录下找，不在整个项目里搜同名文件。
- Android 上的系统打开没有在真机或模拟器上运行，只核对了构建出的清单和路径配置。
- 没有用真实主机和手机走完整流程：手机连的电脑要装上含本分支的桌面版本，回复里的文件链接才可用，此前点链接会提示更新电脑端。iOS 的 Quick Look 也还没在真机上点过。
