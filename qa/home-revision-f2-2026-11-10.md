# 首页改版 F2 批：新建会话和右栏（2026-11-10）

依据：本地设计稿 H-1、H-2、H-4 和新建会话的 N-1～N-3（`designs/agentkib-home-previews/`），交接文档的 F2 批。分支 `home-revision-f2`，基于 `home-revision-f`。

## 改了什么

### 前提：新建的 Codex 会话发不出第一条

问题是真的。Codex 0.167.0 开始一个线程时，要等第一条消息才写 rollout 和状态库里的那一行。AgentKib 读托管会话的事件之前，先核对原生身份（状态库里的一行加上 rollout 头），核对不上就报 `unverified-session-identity`。于是新会话一直打不开，第一条也就发不出去。已读状态因为同样的原因显示“已读状态暂不可用”。

修法：

- `CodexSessions.writtenThreadIds` 和 `SessionReaders.codexThreadWritten` 判断一个线程有没有写下；
- 托管会话读事件时，线程还没写下，就只用这台电脑上的执行记录（这时也没有原生图片可补）；
- 已读状态对还没写下的、AgentKib 自己建的 Codex 线程，直接回答“没有可读的”。

测试 `apps/desktop/test/codex-unwritten-thread.test.ts` 去掉修法就会失败。沙盒里用新建会话的输入框真实发了两次（Codex 0.167.0、API key、本机的模型 mock）：会话建好、打开，第一条消息发出并得到回复，已读状态正常。11-09 在沙盒里看到的 `thread/start` 停在 dispatched，这次没有再出现。

### 新建会话（H1）

首页主区最上面，和会话页工具栏的“新建会话”，是同一个输入框：

- 上面一行：工作区、Agent，选 DeepSeek Harness 时多一个“预设”。
  - 工作区菜单先列最近用过的 3 个，再列全部，可以搜索。最后一行“添加工作区…”选文件夹，加好后自动选中，不离开当前页面。
  - Agent 菜单里，这台电脑上没装的灰显，写“未安装”。
- 输入框下面：“+”直接选文件，权限，右边模型和强度，圆形发送键。Enter 发送，Shift+Enter 换行；和会话页一样，触屏上 Enter 换行。
  - Codex 的权限用 Codex 自己的说法：请求批准、帮我批准、完全访问权限，对应 AgentKib 已有的三种执行策略。完全访问权限显示为橙色。
  - Claude Code 的权限：默认、自动接受编辑、计划模式。不选就沿用这台电脑上 Claude Code 的设置。
  - 模型和强度就是会话页的选择器，默认是所选 Agent 的默认值。只改强度时也带上模型，因为 Codex 要求强度跟着具体的模型。
- 默认选中上次新建会话用的工作区和 Agent。从某个会话点“新建会话”时，默认用那个会话的工作区和 Agent。
- 发送：先在所选工作区用所选 Agent 新建会话。会话目录列出它之后，打开它，由那个会话自己的输入框发出第一条消息和附件。附件在会话建好后上传，因为上传要有会话。
- 失败：
  - 没建成：留在原处，草稿、附件和选项都在，提示原因，代码放在“详情”里。
  - 结果不明：提示“还不确定会话有没有建好，正在核对”，发送键不可用，不重发。核对到已建好就打开那个会话，带上这里的草稿；确认没建成就恢复发送。
  - 建好了但第一条没发出：会话已经打开，草稿留在会话的输入框里，原因用会话页现有的未发送提示。
  - Agent 用不了：提示原因，带“去设置”，发送键不可用。
  - 没有工作区：会话页显示“还没有工作区”和“添加工作区”；首页由入门卡代替，不显示输入框。
- 窄宽度：工作区名截断，Agent 和权限只留图标，模型去掉强度。

会话页工具栏的“新建会话”打开这个输入框，放在页面中间，替换原来的“新建任务”弹窗。

### 右栏（H4），宽 300

每块没有内容时隐藏，三块都隐藏时主区占满。窗口放不下时移到主区下方，三张卡并排。

- 额度：已开启采集且有数据时，显示每个 Provider 第一个可见窗口的已用比例，按接近上限排序，最多 3 行。点进额度页。只读已保存的快照，不在首页触发采集。
- 远程：已开启时显示“已开启 · N 台设备”。本月中继用到 80%、95% 和用完时提示。点进“设置 › 远程连接”。
- 维护：配置问题（N 个工作区）进工作区页并只看需关注的；待审批记忆进记忆；CLI 有新版本进“设置 › 工具”；还有 N 个工作区未诊断，后台诊断完就消失。

### F 批留下的两处

- “还没有会话”那一行不再带按钮，改为“在上方开始第一个会话”。
- 新用户那句说明补上“新建会话”。

### Web 服务

新建 Codex 会话时，Web 服务原来把执行策略写死为“请求批准”。现在接受请求里的 `policyId`，只认这三种策略。选“请求批准”以外的策略等于改执行策略，和会话设置里改策略一样，只有完全访问的设备可以。局域网配对的设备选完全访问权限会被拒绝（403），测试见 `remote-capabilities.test.ts` 和 `code-pairing.test.ts`。

## 与设计不一致的地方

1. **DeepSeek Harness 新建时只有“预设”，没有权限和模型**。会话建好之前，DSH 只报告预设，不报告它的权限预设和模型列表，所以输入框里没有这两项。会话打开后，在会话页的输入框里改。
2. **Claude Code 新建时没有模型选择器**。Claude Code 在会话建好之前不报告模型列表，用这台电脑上的默认模型。会话打开后可以在会话页换。
3. **提示放在输入框上方的页面里，不浮起来**。首页的输入框在页面最上面，上方没有可以浮在其上的内容。会话页也用同样的位置，两边一致。
4. **会话目录列出新会话后才打开它**。会话页会清掉目录里找不到的选中会话，所以新会话进目录之前，输入框保持“发送中”。
5. **第一条消息在打开会话后一分钟内才自动发出**。万一会话打开得很晚，比如中途离开了页面，草稿放回会话的输入框，不自动发。
6. **右栏的远程卡只写设备数**。设备记录里没有“最近在线”。
7. **右栏没有“终端插件或 DSH 插件需要更新”**。Claude 终端插件的状态是按会话的；DSH 插件的说明只在 DSH 会话的“会话操作”里，首页没有单一的入口。
8. **右栏的 CLI 新版本只在检查过之后出现**。检查要运行每个 CLI 并联网，首页只用“设置 › 工具”已经检查过的结果。
9. **会话索引关闭时，首页不显示输入框**。新会话要在会话页打开，会话页需要会话索引。

## 性能

首页进入时读一次所选 Agent 的选项。界面缓存 5 分钟。Codex 的模型列表由后端缓存，第一次读会启动一个 app-server，之后直接返回。不跑诊断，不检查 CLI，不采集额度，不轮询。

## 没验证到的

- **Claude Code 的第一条**：沙盒里没有装 Claude Code。新建请求的内容由测试覆盖，打开会话后发第一条和 Codex 走同一段代码。
- **你的真实环境**：没有用你的 Codex、Claude Code 登录跑。
- **桌面窗口最小 1280 宽**，所以首页和会话页的输入框实际不会窄到收起；收起规则留给 F3 的 Web。
