# 首页改版 F3 批：Web 首页和“需要你处理”就地作答（2026-11-11）

依据：本地设计稿 W-1、W-2（`designs/agentkib-home-previews/`），C-1～C-3 的卡片，改版计划第 3 节和 H3、H6，交接文档的 F3 批。分支 `home-revision-f3`，基于 `home-revision-f2`。

## 改了什么

### 共享部分

这批把各 Agent 的规则从两端界面里移到共享包，桌面、Web 和之后的菜单栏只负责画。以后新增 Agent，改这几处即可：

- `packages/session-ui/src/new-session.ts`：新建会话的模型。
  - 内容：能新建会话的 Agent 列表；各 Agent 的权限选项，用 Agent 自己的说法；预设；新建请求的字段；输入框的全部文案（四种语言）。
  - 桌面输入框改用它，删掉桌面语言包里 36 个 `newSession.*` 键。
  - 新增一条规则：Codex 选“请求批准”以外的策略要求完整访问，和主机一致。没有完整访问的浏览器只列“请求批准”，不列主机会拒绝的选项。
- `packages/session-ui/src/interaction-items.ts`：审批和问题卡片的条目，说明这台设备能做什么、不能做时为什么。会话页和首页共用；桌面和 Web 会话页的卡片外壳改用它。
- `packages/session-ui/src/home-sessions.tsx`：首页的分组列表。
  - 两种排法：宽屏把状态标签放在行尾；手机宽度把状态放在第二行开头并上色。
  - 另外包括“一切就绪”、最近会话、行内卡片，文案四种语言。
  - 桌面首页改用它，删掉桌面语言包里 7 个首页键。
- `packages/session-catalog/src/home.ts`：首页分组规则，从桌面 `home-sessions.ts` 移来，并新增“结果待核对”的会话。
- `packages/web-client`：
  - `needsDurableReceipt`：哪些 Agent 和执行方式会留下回执。两端会话页控制器改用它，不再各写一份 Agent 列表。
  - `replyToInteraction`：在会话页之外作答。
    - 先重新读访问权限和会话状态。
    - 卡片显示的请求必须原样还在；设备必须有相应权限。
    - 要留回执的 Agent，先在本浏览器记下请求 ID 再发送。
    - 主机说没执行就删掉记录；结果不明就保留记录，不重发。
  - `settledReceipt`：只有请求、会话和操作都对得上的回执，才算有了结论。
- 会话页的卡片组件加了 `onDismiss`。放在首页行里时，✕ 和 Esc 收起这一行，不会收成输入框上方的一行。

### 就地作答（桌面和 Web）

- “需要你处理”里的审批和问题，点一下就在这一行里展开会话页的同一张卡片，下面有“打开会话”。“结果待核对”的行点了直接打开会话。
- 卡片展开时读一次这个会话的当前状态。请求已经不在等待时，写“这个请求已经不在等待，可能已在别处处理”。
- 作答被接受后：
  - 会话还有别的请求，就显示下一个；
  - 没有别的请求，这一行收起，并从“需要你处理”去掉，直到目录报告新的状态（最多 15 秒）。
- 没发出去：原因写在卡片上，可以再答。
- 结果不明：
  - 不重发，这一行改列为“结果待核对”，请求 ID 记在本浏览器的待核对记录里；
  - 主机的回执说明执行了或没执行之后，记录自动清掉，这一行回到目录报告的状态。
  - 桌面首页在主机通知回执变化时核对；Web 首页收到回执通知时核对，Web 会话页的控制器也照旧核对。
- Web 断线时，卡片只显示请求，写“已断线，连上后才能作答”。

### Web 首页（W-1、W-2）

**宽屏**

- 侧栏最上面是“首页”，右侧是“需要你处理”的数量；点 AgentKib 标志也回到首页。
- 主区：
  - 最上面是新建会话。这次访问不能新建或不能发送时隐藏。
  - 下面是需要你处理、待查看、进行中三组；不列最近会话，也没有右栏。
- 去掉原来的“选择一个会话”空状态，以及它的两个文案键（桌面那份会话界面里对应的两个键一并删掉）。
- 右上角铃铛的数量就是“需要你处理”的数量。点开后列出这些会话和各自的状态。

**手机宽度**

- 先显示首页，顶部用“首页 | 全部会话”切换；“全部会话”就是原来的会话目录。
- 右上角“+”打开新建会话的面板，这次访问不能发送时不显示。
- 每行的状态写在第二行开头并上色，标题单独一行，过长截断。
- 下面列最近 3 个会话，附“全部会话”链接。
- “已授权浏览器”和退出只在“全部会话”底部。

**断线**

沿用原有的断线提示条：列表保留最后一次的内容，会话仍可打开阅读，作答、新建会话和“+”都不可用。

**目录状态点**

没改规则，目录和首页读的是同一份目录数据：等你处理是琥珀色点，有未读结果是主色点，正在运行是转圈。结果待核对的会话，在目录行上加原有的“待处理”标记。

### Web 新建会话

- 用桌面的同一套输入框和规则：工作区、Agent、各 Agent 自己说法的权限、预设、模型和强度、附件。默认用上次新建会话的工作区和 Agent，没有记录时用最近有会话的工作区。
- 和桌面一样：会话目录列出新会话后才打开它，第一条消息由新会话自己的输入框发出；没建成时草稿留在原处；结果不明时不重发，核对到已建好再打开。
- Web 会话页的输入框移植了 F2 的改动：自动发出带来的第一条；发出前被改过，或晚于一分钟才打开，就只放回草稿。
- 删掉 Web 的“新建任务”弹窗（会话界面里的新建模式）和只测它的测试。原来靠它的“结果不明的新建在重连后核对”，现在由新的 `use-new-session` 负责，并有测试。

### Web 的合成服务

`apps/web/scripts/qa-server.mjs` 补了合成数据：4 个工作区、8 个会话，覆盖等待审批、有问题待回答、未读的成功和失败、终端里运行和普通会话。另外有：

- 每个会话各自的状态，可以作答；
- `managed/options` 和 `managed/create`，以及回执；
- 变化时推送目录通知；
- 开关：`QA_APPROVED=1`（跳过配对）、`QA_HOME=clear`（一切就绪）、`QA_REPLY=unknown`（作答和新建时断开连接）、`QA_DEVICE=readonly`（不能发送、不能新建）。

## 与设计或交接文档不一致的地方

1. **侧栏的“待查看”条（已处理）**：按你的决定，宽屏显示首页时不再显示这一条，首页旁边已经列出了待查看；打开某个会话时，或者手机切到“全部会话”时，照常显示。
2. **手机宽度的最近会话固定 3 条**，按交接文档写；W-2 的“一切就绪”那张画了 5 条。
3. **“已运行 N 分钟”只出现在 Codex 应用里运行的轮次**。在终端或 AgentKib 里运行的，目录不报告开始时间，显示最后更新时间，和桌面首页 F 批相同。
4. **颜色跟随主题**。设计稿的主色是蓝色，应用默认主题的主色是近黑色，所以发送键、“+”和未读点是黑色。
5. **宽屏的新建会话多了“权限”**。和桌面一致；W-1 没画。
6. **手机的“+”打开的是固定在顶部的面板**，不是从底部弹出，这样键盘弹出时输入框不会被挤出屏幕。只在 390×480 的视口里模拟看过，见“没验证到的”。
7. **手机宽度的铃铛显示数字**。W-2 画的是小圆点，这里和宽屏一致。
8. **Web 不能添加工作区**，新建会话里没有“添加工作区…”。Agent 用不了时也没有“去设置”。
9. **会话索引关闭时**，Web 不能开启索引，所以首页没有“开启”按钮。手机宽度只写一行说明，宽屏由旁边的目录说明。

## 验证

- 新增和改写的测试：
  - 首页分组：结果待核对的会话不再作为可作答的请求列出（`home-sessions.test.ts`）。
  - 作答函数：先记下请求 ID，按当前版本发送，被接受后删掉记录；请求变了就不发；没有权限不发；记录写不进去就不发；主机说没执行就删掉记录，结果不明就保留；回答问题用共享的请求体；没有回执的 Agent 不留记录；访问已结束；回执要对得上请求、会话和操作才算有结论（`apps/web/src/interaction-reply.test.ts`）。
  - 桌面首页：在行里展开卡片并作答；结果不明时收起且不重发；结果待核对的行打开会话；刚答完的请求不再列出，以及卡片下的“打开会话”；请求已经不在等待（`HomeSessions.test.tsx`）。
  - Web 首页：宽屏有输入框和三组、没有最近会话；不能发送时隐藏输入框；手机宽度的状态写法和最近 3 条；一切就绪；在行里作答；结果不明时列为“结果待核对”；回执说明已执行后恢复；断线时列表保留、不能作答和新建（`session-home.test.tsx`）。
  - Web 外壳：“首页”和铃铛的数量；标志和“首页”回到首页；手机宽度的切换，已授权浏览器在“全部会话”里；“+”只给能发送的访问（`session-workspace-home.test.tsx`）。
  - Web 新建会话：最近的工作区，交出第一条；没有完整访问时只列“请求批准”；只改强度时带上模型；没建成留下草稿；结果不明时不重发、核对到已建好再打开；Claude Code 只在选了权限时传；DSH 只在非默认预设时传；Agent 用不了；断线时不能发送（`new-session-composer.test.tsx`）。
  - Web 会话页输入框：移植 F2 的三项第一条测试（`session-composer.test.tsx`）。
- 本地按 CI 跑了全部检查，全部通过：
  - 全量格式检查、lint（只有原有的警告）；
  - backend、desktop、web 三处类型检查；
  - 构建：协议生成、cursor 与 frpc 打包、web、renderer、backend、electron，以及 Web 托管版；
  - Web 测试：86 个文件、1796 项通过；
  - 桌面测试：527 个文件通过，1 个跳过；10244 项通过，3 项跳过。
- 之后又改了 3 处：卡片区域限宽、行尾箭头去掉旋转动画、合成服务作答后把 `pendingInteraction` 置为 false。改后重跑了格式检查和首页、新建会话的相关测试。

## 没验证到的

- **真实手机或模拟器上的键盘**：没有做，只在无头 Chrome 里用 390×480 的视口模拟键盘弹出后的可见区域。
- **真实 Agent 的审批和问题**：桌面用主进程里合成的请求和结果，Web 用合成服务，没有用真实的 Codex 或 Claude Code 走一遍就地作答。作答的请求体和检查由测试覆盖，和会话页用同一套请求。
- **桌面断网**：桌面连的是本机的主机，没有做断网场景；Web 的断线用停掉合成服务模拟。
