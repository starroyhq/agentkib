# 菜单栏 T-2：状态图标和浮窗（2026-11-11）

依据：本地设计稿 T-2（`designs/agentkib-menubar-previews/T-2-menu-bar-popover-agentkib.png`，v15 .pen 的 `oGWxe`），以及 11-09 定下的约束：图标保持黑白模板图，只用形状区分状态。和 F3 在同一分支 `home-revision-f3`（基于 main `bcb34fcc8`）。

## 改了什么

### 菜单栏图标

- 只用形状区分状态，颜色由系统按菜单栏深浅决定：
  - 空闲：只有标志；
  - 有会话在运行：标志略缩小，外面一段弧转动（12 帧，每帧 125 ms）；系统打开“减少动态效果”时，弧停在右侧；
  - 有事等你处理：右上角一个小圆点，和标志之间留一圈空隙，旁边用菜单栏标题写数量。等你处理优先于转圈。
- 这些状态由主进程用原有的 44 px 标志合成（`tray-icon-images.ts`），没有新增素材。
- Windows 的托盘图标本来是彩色的：弧用标志的蓝色，小圆点用红色。Windows 托盘不能显示文字，数量写在悬停提示里。
- 状态由主进程的 `TraySessionWatcher` 读本机会话目录得出，计数规则和首页相同：需要你处理包括等待审批、有问题待回答、结果待核对。
- 为了空闲时不耗资源：
  - 只有在有会话运行时才订阅目录变化。订阅期间，后端每 2 秒读一次目录，和窗口订阅时一样；
  - 没有会话运行时每分钟读一次；
  - 控制操作完成、其他窗口看到目录变化、打开浮窗时，立刻再读一次；
  - 会话索引关闭时，图标保持空闲。

### 浮窗

- 宽 360 px，高度随内容，最多 720 px 或屏幕剩余高度，超出时中间的列表滚动。深色跟随应用主题，Esc 关闭。
- **标题行**：
  - AgentKib，每个 Agent 一个额度小圆环（最多 3 个），右侧是设置齿轮。
  - 圆环显示剩余比例，低于 20% 变琥珀色，低于 10% 变红色。
  - 点圆环在原处展开这个 Agent 的各窗口：剩余比例、重置时间，以及刷新按钮和“打开额度页”。
- **新建会话一行**：
  - 默认用上次新建会话的工作区和 Agent，和 F2 的输入框共用这份记录；标签可以改。
  - 回车用 F2 的同一个新建请求建会话，模型、权限和预设都用默认值。随后在主窗口打开这个会话，第一条消息由会话自己的输入框发出，和 F2 相同。
  - 开始输入后才读 Agent 的选项，因为 Codex 第一次读选项会启动 app-server。
- **需要你处理**：
  - 每次打开时，第一条审批自动展开成紧凑卡片：要做什么、命令或文件（最多 3 行）、“允许一次”“拒绝”和“更多选项”。
  - 走首页同一条控制路径：检查请求是否原样还在、设备权限，记下请求 ID。结果不明时不重发，这一行改列为“结果待核对”。
  - 问题、表单、其余选项，以及“更多选项”，都打开主窗口里的这个会话。
- **进行中**：
  - 悬停或聚焦时出现“停止”，和作答一样先检查、记下请求 ID。
  - 在其他应用里运行的轮次（Codex 应用）不提供停止。
- **待查看**：结果和时间。点开在主窗口读，按现有规则标为已读。
- **远程访问**：
  - 设置过远程后才出现，状态写法和远程页相同：已开启 · N 台设备、正在连接、连接中断、已暂停。
  - 远程已开启时，有已配对设备在线就写“设备名称 在线”，多台写“某某 和另外 N 台在线”。在线的判定：这台设备正连着事件流，或者一分钟内发过请求。Web 服务只在内存里记最近一次请求的时间，状态里每台设备多一个 `online`。只看远程（本机和中继）这一路的设备，局域网单独配对的设备不算。
  - 关掉开关就是暂停（`relay-stop`）。打开开关用保存的连接恢复；恢复不了（例如需要登录），就打开远程设置页。
- **底栏**：打开 AgentKib、退出。
- **其他状态**：
  - 没有要处理、进行中和待查看的会话时，写“一切就绪”；
  - 会话索引关闭时，提示去首页开启；
  - 第一次读目录时显示占位行。

### 右键菜单和 Linux

- macOS 和 Windows：左键打开浮窗，右键只有“打开 AgentKib”和“退出 AgentKib”。
  - 原来右键菜单里的查看额度、刷新额度、工作区状态、MCP Hub、设置、刷新全部都去掉了。设计稿的说法是：别的都在浮窗里。
  - Windows 原来左键打开主窗口，现在也打开浮窗。
- Linux 只有原生菜单：打开 AgentKib；需要你处理 N 项（有事等你时才出现，点了打开首页）；退出 AgentKib。

### 主窗口和主进程

- 新 IPC `shell.openMain`：浮窗让主窗口打开首页、某个会话、额度页或设置页。字段逐个校验，其他页面和字段一律不放行。
  - 会话要等目录列出后才打开，最多等 15 秒。
  - 新建的会话还带着第一条消息，交给它的输入框发送。
- 新 IPC `shell.setPopoverHeight`：浮窗告诉主进程内容高度。
- 账号请求原来只信任主窗口。现在浮窗也可以读账号状态（只放行 `status` 一项），用来确定已读状态属于哪个账号；主进程也把账号状态的变化发给浮窗。没有这一项，浮窗读不到已读状态，“待查看”是空的。

### 共享部分

- web-client `stopSessionTurn`：在会话页之外停止正在运行的轮次。它和 `replyToInteraction` 共用重读状态、检查和待核对记录的逻辑；桌面的 `useHomeReplies` 加了 `stop`。
- session-ui 新增 `CompactApprovalCard`（紧凑卡片）和 `ApprovalChoice.quick`，用来标出可以一键回答的选项：允许一次、拒绝、拒绝并停止本轮。
- 删除：
  - 旧的额度浮窗 `QuotaPopover.tsx`；
  - 只给它或旧右键菜单用的文案键：`tray.*` 13 个，以及 `quota.popoverEmpty`、`quota.openDashboard`；
  - `api.openQuotaDashboard` 和主进程的 `open-quota-dashboard` IPC。

## 与设计稿不一致的地方

1. **远程那一行的“设备名称 在线”（已补上）**：最初只写“已开启 · 1 台设备”，按你的决定补上了在线设备的名称，规则见上面的“远程访问”。
2. **运行时间只在 Codex 应用的轮次里按秒计**。在 AgentKib 和终端里运行的，目录不报告开始时间，所以显示最后更新时间，和首页相同。地点写“AgentKib”“终端”或应用名。
3. **额度重置时间写相对时间**（“3 小时后重置”），和额度页一致。设计稿写的是“19:40 重置”“周四重置”。
4. **有的审批没有单纯的“拒绝”**。例如 Codex 请求在沙箱外运行命令时，只有允许、总是允许和取消三项。这时紧凑卡片的第二个按钮是“拒绝并停止本轮”。
5. **新会话一开始的标题是 Agent 名**（如“Codex”），等 Agent 起好标题后才更新。设计稿画的是任务标题。
6. **打开浮窗不再自动刷新额度**。旧额度浮窗在开了“自动获取额度”且数据过期时会刷新一次。新浮窗打开得更频繁，额度改由原有的定时刷新和面板里的刷新按钮负责。
7. **浮窗里不能添加工作区**。工作区标签的菜单只列最近 8 个工作区和三个 Agent。

## 没验证到的

- **真实菜单栏图标**：没有截真实的菜单栏（会拍到别的应用的图标），截图是同一合成代码的渲染结果。
- **Windows 和 Linux**：没有实机。浮窗位置、右键菜单和 Linux 原生菜单只由测试覆盖。
- **Claude Code 和 DSH 的审批在紧凑卡片里的样子**：只用 Codex 走了一遍；Claude 的允许和拒绝由模型测试覆盖。
- **远程开关的真实效果**：沙盒没有设置远程。暂停和恢复的请求由测试覆盖。

## 另外发现

- 桌面的全局样式给 `button`、`input`、`select`、`textarea` 设了 `font: inherit`，而且不在 Tailwind 的层里，所以这些元素上的字号类不生效，字号总是跟随父元素。浮窗里把字号放在外层或内部的 `span` 上绕开了。
- 首页等处按钮上的字号类同样不生效，例如 F3 首页的“查看全部”。要不要把这条规则移进 `@layer base`，会影响全应用的按钮字号，这次没动。
