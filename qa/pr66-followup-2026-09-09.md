## 第三轮：启动恢复、SSE 开销与 Windows 超时夹具

- Windows run `34342201889`：文件身份相关测试已通过，x64 剩余失败为 `command_timeout_terminates_the_windows_job_object` 的 descendant 未就绪。两层 PowerShell 冷启动占用了原 12 秒超时；原延迟 marker 断言也不能可靠证明终止。改为 Job Object 附着后放行子进程、独立有界就绪等待，再执行生产共用的 100ms 超时逻辑；保留真实子进程句柄，在 job guard 仍存活时确认退出。
- 评论 `3967573227`：Claude 的同步启动失败不再永久置为 unsupported。恢复发送前状态并推进 revision，要求重新同步后显式重试；已有 worker 的投递失败仍为 outcome-unknown，禁止自动重放。缺失管道时先清理尚未收到输入的子进程。
- 评论 `3967573240`：SSE 不再逐分片编码和扫描全部已累积前缀。按新片段计数、完成行后拼接，保留字节上限和 Unicode 边界。4 MiB / 1 KiB 分片回归约束总编码量不超过输入两倍，不使用计时断言。
- 全量验证额外暴露文件锁释放竞态：并行 fork 可能暂留同一 open-file-description，仅关闭 owner 文件不会立即释放 flock。SessionLock 显式 unlock 后关闭；确定性 dup 回归验证旧继承描述符不阻止新 owner，也不释放新 owner 的锁。
- 本机 `cargo test --workspace`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo fmt --all -- --check` 通过；Claude runner 20 项通过。
- `pnpm test`：桌面 668 通过、既有真实 Claude opt-in 1 项跳过，Web 129 通过。`pnpm typecheck`、`pnpm format:check`、内置 Web、托管 Web 与桌面渲染构建通过，`git diff --check` 通过。
