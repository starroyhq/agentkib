# 资源占用修复与对比验证

日期：2026-11-12。环境：macOS arm64、Node 26.13.0、Codex CLI 0.167.0。

对比基线为 `35f9a843567623f2530cc052c245c2869ded67ff`，候选为本次未提交的工作树。各场景使用相同输入和独立进程、临时数据目录；没有调用模型、读取生产凭据或写入原生会话。未替换已安装的 AgentKib，也未停止其他开发任务。

## 定位与修复

1. `codex-managed/executions.sqlite` 的只读调用原来反复打开可写连接、准备 schema、修改权限并关闭连接，造成 WAL/SHM 与元数据反复写入。现在使用只读连接并在 Runtime 内有界复用；每次仍校验目录、文件身份及权限，替换时关闭旧句柄。只有写路径升级 schema。
2. 托管 Codex 每个流式文本片段都保存完整执行快照。现在通知不合并，临时文本持久化按 250ms 合并；结束、审批、控制边界和正常关闭立即保存。增量字节数改为增量计算，处理分片的 Unicode 代理对。强杀可能丢失尚未保存的临时预览，250ms 不是繁忙事件循环下的严格上限。
3. 原生已读巡检重复调用 `thread/read` 和 `thread/turns/list`，反复解析完整历史。现在仍每 5 秒核对，以原生状态数据库目录回执为权威，未变化时复用结果投影；变化、通知、确认及旧 CLI 回退保留完整核对。相同状态不再写阅读账本或广播全局失效。
4. 单会话定位原来先读取所有线程再筛选。现在记忆有界的原生 ID 提示，SQL 按 ID 查询，每次仍读取最新归属与文件信息。首次未知不透明 ID 的查询仍可能扫描目录。
5. 已索引 Codex 静态历史快照启用现有 32 项／8 MiB 有界缓存，版本包含索引代次、工作区范围、文件身份与纳秒时间；控制与实时状态仍新鲜读取。无游标轮询不再额外保留分页游标。
6. 桌面与网页的会话快开缓存由仅限制 10 项，改为同时限制 32 MiB 估算正文与结构预算。当前已加载会话不截断，超大页不额外驻留；切换身份和迟到响应隔离沿用原语义。

## 相同场景实测

### SQLite 与流式持久化

独立 Node 进程、真实临时 SQLite；每版执行 1,000 轮读取，以及 600 个 32 B 文本增量（间隔 20ms）和结束事件。

| 指标             |        修改前 |      修改后 |
| ---------------- | ------------: | ----------: |
| 读取耗时         |      2,526 ms |      129 ms |
| 读取 CPU 时间    |      2,105 ms |      141 ms |
| 读取归属磁盘写入 | 147,439,616 B |         0 B |
| 流式 CPU 时间    |        804 ms |      103 ms |
| 流式归属磁盘写入 |  56,934,400 B | 1,781,760 B |
| 流式保存次数     |           602 |          51 |
| 发布通知次数     |           602 |         602 |
| 最终保存正文     |      19,200 B |    19,200 B |

该读取路径写入降为零；流式写入减少 96.9%，最终正文和通知完整。磁盘数据来自 macOS `proc_pid_rusage`，属于进程归属 I/O，不等同于 SSD 物理磨损；其他平台无法测量时输出 `null`，不能当作零。

报告：`/tmp/agentkib-managed-io-benchmark/repro-comparison.json`。

### 真实 Codex 原生回执

独立真实 Codex app-server、隔离 HOME/CODEX_HOME、禁止网络；使用 65,853,615 B 合成 rollout，执行四次、间隔 5 秒的已读巡检。

| 指标                |   修改前 |  修改后 |
| ------------------- | -------: | ------: |
| 原生进程 CPU 时间   | 138.9 ms | 11.3 ms |
| `thread/read`       |        8 |       0 |
| `thread/turns/list` |        4 |       0 |
| `thread/list`       |        4 |       4 |

原生 CPU 减少 91.9%，轮询间隔保持不变。真实 RPC 验证原生手动未读、原生已读及新增结束结果均能更新。

两侧归属物理读取均为零，属于暖页缓存结果，不能声称物理读盘减少了某个百分比。重复完整历史工作减少由 RPC 次数与 CPU 时间佐证。归属写盘分别为 4 KiB 和 16 KiB，不用这组小样本宣称写盘改善。

报告：`/tmp/agentkib-read-state-benchmark-final-20261112.json`。

### 单会话定位

真实临时 SQLite，5,000 个线程、51 个工作区、60 次查询：返回行数从 300,000 降到 60；耗时从 1,668ms 降到 274ms，CPU 从 2,187ms 降到 280ms。返回行数不是物理磁盘读取量。

### 长会话缓存

两个独立 V8 进程打开相同的 10 个会话，每个会话 1,500 条、每条约 8 KiB，保留当前页并在 GC 后测量。

| 指标           | 仅限制项数 | 同时限制字节预算 |
| -------------- | ---------: | ---------------: |
| 驻留缓存会话数 |         10 |                1 |
| 堆内存增量     |  120.5 MiB |         13.2 MiB |
| RSS 增量       |  231.4 MiB |        230.1 MiB |
| 当前页保留条数 |      1,500 |            1,500 |

缓存驻留堆减少约 89%。RSS 没有明显下降，V8 仍可能保留内存页；这不是整个 Electron 的 RSS 降幅，也不证明活跃长会话、图片解码或全部 DOM 内存已解决。

报告：`/tmp/agentkib-resource-comparison/transcript-cache.json`。

## 复测入口

在仓库根目录执行。`--baseline-root` 指向基线提交的冻结源码，所需依赖沿用当前安装；不要把正在修改的目录当作基线。

```sh
node apps/desktop/scripts/benchmark-managed-io.mjs --baseline-root /path/to/frozen/source
```

这些入口只测各自路径，不应把不同场景的百分比合并或外推为整个应用的节省比例。原始 JSON 位于本机临时目录，结果已记录在本文件中；可通过入口重新生成。
