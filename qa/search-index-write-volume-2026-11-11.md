# 会话正文索引写入量修复

日期：2026-11-11。基于 `main` 的 `970698315`，分支 `claude/search-index-write-storm`。

## 问题

macOS 记录了 8 份 AgentKib Helper（0.26.1）的磁盘写入超限报告，最严重的一份在 2.4 小时内写入 549.76 GB，平均 63 MB/s，调用栈是后端经 Node 内置 SQLite 到 `pwrite`。写入的文件是数据目录下的 `session-search.sqlite`。

出问题的索引（只读取了元数据，未读正文）：文件 1024 MB，空闲 3 MB，超预算标志为真；2590 条会话全部标记 `cache-budget-exceeded`，其中 2498 条从未建成索引。

## 原因

1. 超预算后没有退路。没有可用版本的会话每一轮都执行“登记开始构建、发现超预算、登记中止、截断式 checkpoint”，2590 条会话一轮就是五千多个写事务。超预算标志只在索引格式升级时清除，预算按文件总页数计算，包含已删除的空闲页。
2. 调度没有节流。目录变化、任何失效事件、会话转为空闲都会立刻触发一轮，每轮遍历全部会话。
3. 没有增量。会话记录一变就整条重建：全部分块重新插入，旧分块全部删除。
4. 读取失败的来源同样每轮写两个事务。

## 改动

- 重建只写有变化的分块。开始构建时读出已提交分块的位置和内容哈希（新增覆盖索引 `chunks_identity`），新快照里相同的分块原样保留，只插入不同的、删除消失的。提交时新分块并入原有代际，未变化的行不改写。解析、脱敏、归属校验仍对完整来源执行，语义不变。
- 无法索引的会话只记录一次（`markUnindexed`），状态不变则不写入；超预算时在开启代际之前就拒绝。
- Claude Code 与 Codex 的记录文件按路径、设备、inode、大小、修改时间留存文件戳（新增表 `source_stamps`，与所属来源版本绑定）。文件戳未变时不读文件，即使是强制刷新。其他来源还依赖数据库或运行中的进程，仍按完整来源版本核对。
- 预算可淘汰：写满时删除更新时间更早的会话正文，直到回到 90% 以下；没有更旧的可淘汰时该会话等待。超预算标志只在确有删除、且占用低于 90% 时清除，避免装不下的会话每轮被暂存再丢弃。占用按“总页数减空闲页”计算。
- 单条会话最多保留约 32 MiB 正文（预算的 1/32；实测索引占用约为正文的 7.4 倍），超出部分不索引，标记 `cache-session-limit` 和部分覆盖。保留开头而不是末尾，是为了让已索引的前缀在会话增长时不被改写。
- 调度：后台两轮之间至少 30 秒；刚重建或读取失败的会话等待 60 秒，连续变化时逐步延长到 10 分钟，等待结束后自动补一轮；按更新时间从新到旧处理。手动重建、开启索引、来源失效不受间隔限制。
- 写放大：WAL 同步级别改为 NORMAL，自动 checkpoint 从 256 页调到 2048 页，去掉逐分块的两次 PRAGMA 预编译，中止后只在丢弃超预算代际时截断 WAL。
- 顺带修复：清理索引后 DeepSeek Harness 会话不会重新索引（清理时没有重置“已索引”记录）。

兼容性：没有升级索引格式版本号。新增的索引和表由旧版本忽略；旧版本写入新代际后留下的文件戳因来源版本不符而失效。已写满的旧索引不需要清空，升级后按从新到旧重新索引，逐步淘汰最旧的正文。

## 写入量实测

一条 2000 条记录、13.66 MB 正文的合成会话，关闭自动 checkpoint，用每次操作后的 WAL 大小计量：

| 操作                             | 写入 WAL  |
| -------------------------------- | --------- |
| 首次建立                         | 241.55 MB |
| 整条重建（修复前每次变化的代价） | 293.00 MB |
| 追加一轮后重建（10 次平均）      | 0.13 MB   |
| 内容未变时重建                   | 0.02 MB   |

追加一轮的写入量约为整条重建的 1/2300。索引文件 101.56 MB，为正文的 7.4 倍。

## 测试

- 存储层新增 9 项：只重写变化的分块、替换与删除、放弃重建后保留已提交分块、无法索引只记录一次、来源不可读时保留可搜索的旧正文、淘汰顺序、删除后恢复索引、单条会话上限、文件戳只对所属版本有效。
- 真实 Router、Backend 和搜索 Worker：未变化的记录文件多次强制刷新后行与提交记录都不变；追加一轮后原有行不变，只多一行。
- 调度：一阵变化只跑一轮且两轮之间等待；持续变化的会话在等待结束后自动补上；写满的缓存在后续各轮不再产生提交。
- 现有搜索索引测试全部保留。其中依赖“改完立刻索引”的用例通过环境变量 `AGENTKIB_SEARCH_PASS_INTERVAL_MS`、`AGENTKIB_SEARCH_RETRY_WAIT_MS` 把间隔设为 0。

完整的类型、lint、格式和全量测试结果见 PR 说明。

## 未覆盖

- 没有在真实应用里做长时间运行的写入量观测。发布后可检查 `/Library/Logs/DiagnosticReports` 是否还出现 AgentKib Helper 的 disk writes 报告。
- 判断来源未变化时，Claude Code 与 Codex 之外的来源仍要读取完整来源，只是不再写入；后台间隔把这类读取限制在每 30 秒一轮以内。
- 首次建立索引的写入量约为索引大小的 2.4 倍，本次没有优化。
