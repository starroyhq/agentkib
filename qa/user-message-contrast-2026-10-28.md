# 用户消息气泡里的代码、引用和链接（2026-10-28）

分支 `feat/claude-code-followups`。问题来自 [工具详情真实模型验收](conversation-tool-details-real-model-2026-10-27.md) 的第 6 条观察：用户消息气泡里的行内代码几乎看不见。

## 原因

用户消息的气泡是 `--primary` 底、`--primary-foreground` 字，气泡里的 Markdown 却沿用为页面底色设计的样式：

- 行内代码填 `--muted`，代码块填 `--muted` 的 40%；
- 引用用 `--muted-foreground`；
- 桌面工作区会话列表的 `.markdown-content` 另有一套：代码填 `--muted` 的 78%，代码块 72%，链接用 `--primary-text`。

`--muted` 接近 `--primary-foreground` 的主题里，行内代码就成了白底白字（Web 浅色、桌面 VTRON 浅色）或深底深字（Web 深色、桌面 Claude 深色等）。

涉及三处：Web 会话页（`apps/web/src/style.css`）、桌面会话页（`conversation.css`）、桌面工作区会话列表里的彩色用户消息（`ConversationEventRow`）。

## 修复

只改用户消息里的 Markdown，Agent 消息不变：

- 行内代码和代码块不再填色，沿用气泡的文字颜色，用文字颜色 40% 的细线标出范围；
- 引用和链接继承气泡的文字颜色，引用左边线为文字颜色的 50%；
- 桌面会话列表的彩色用户消息加 `markdown-on-primary` 类，套用同样的规则。

因此这些元素的对比度与气泡正文相同。各主题的正文对比度已由现有的主题对比度测试保证不低于 4.5:1。

## 验证

浏览器实测：

- 用 playwright-cli 在 Chromium 中加载临时页面。Web 端渲染生产的 `SessionTranscript`；桌面端渲染会话页的 `SessionTranscript` 和会话列表的 `ConversationEventRow`。各自加载生产 CSS。
- 合成消息里有行内代码、代码块、引用和链接。
- 颜色取自计算样式，与半透明的祖先背景叠色后，按 WCAG 公式计算对比度。
- 覆盖 Web 3 套配色和桌面 5 套主题，各分浅色和深色。临时页面用后已删除。

修复后，每套主题里这些元素的对比度都等于该主题气泡正文的对比度；桌面最低值 4.55 是 Claude 浅色正文本身的对比度。Agent 消息里的代码修复前后相同。截图核对过 Web 浅色与深色、桌面 VTRON 浅色、Claude 深色和 Minimal 深色：代码可读，细线可见，气泡布局不变。

其他检查：

- `apps/desktop/src/core/theme-contrast.test.ts` 新增 26 项（Web 6 套、桌面会话页 10 套、桌面会话列表 10 套）：从三份 CSS 读取用户消息的规则，按各主题的颜色计算行内代码、代码块、引用和链接的对比度。修复前 26 项都失败（缺少规则），修复后通过。
- 变异检查共 10 处，每处把一条规则改回页面底色的取值或删掉。其中 9 处让测试失败。剩下一处是把 Web 代码块改回 `--muted` 的 40%：Web 配色下仍有 4.53，高于阈值，测试允许它是对的。
- Web 生产构建保留了这些规则。Lightning CSS 为不支持 `color-mix` 的浏览器生成了回退，细线改用不透明的文字颜色，新写法放在 `@supports` 里。
- 全量：后端构建，后端、桌面、Web 类型检查，`oxfmt --check`、`git diff --check` 通过；`oxlint` 警告数与基线相同（276）；桌面 449 个文件中 448 个通过、1 个跳过，8967 项通过、3 项跳过；Web 72 个文件 1590 项通过。
