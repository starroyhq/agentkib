## 实施记录

### Agent 与集成

- 概览仅在查询成功且存在可用的已导入用量时显示卡片；不可用、加载或错误缓存不显示任何用量内容
- 用量标签使用“暂时读不到 {Agent} 的用量”，保留具体本地化原因、可折叠原始诊断及重试
- 列表只显示搜索，已安装且有数据者优先；保留兼容深链接筛选、显式选择及异步初始化规则
- 支持能力只显示能力名，控制为实验性烧瓶图标；不支持项灰显，全局资产卡标题改为“全局配置”
- 本页标题减少空白，本机服务说明和操作按钮统一置于卡片内边距中，其他设置页默认布局不变

### 技能与 MCP

- 分段和资源库侧栏计数改为灰色数字；只调整本批指定标签，其他页面和全局 Badge 样式不变
- 原生技能只显示个人或项目一种来源，相关工作区留在更多菜单；来源与显示路径同行，所有操作仍使用原始路径及观察身份
- Agent 标签浅灰、带图标并置于“可见于”后；正常检测状态省略，原生限制、信任及未验证等异常独立成行
- 只读说明集中一行，ⓘ 可悬停或点击，撤销部署筛选按实际数据出现；别名、管理归属、同步及其他操作保持可达
- MCP 说明移到页头，高级摘要折叠时可见；逐 Agent 对话框标题与菜单文案分开，中文后缀按拉丁/数字边界留空格

### B3·C 遗留

- 复制成功反馈 3 秒清除，连接、会话、激活状态和连接代际变化即失效；旧 Clipboard 完成和计时器不会改写新状态
- 手机授权说明合成一段，完整保留现有及以后新增工作区、无需电脑再次确认、只读/完整控制权限及仅限自己设备的范围
- 浏览器和附近电脑空列表给出明确提示；首次加载、失败和操作中不误报空
- Web 没有这些桌面管理页或终端连接面板，不新增 Web 管理能力；全局字典四语同步，现有镜像文件保持相同

## Skills 文件系统超时定位与修复（2026-10-23）

### 与 D 收尾的关系及证据边界

- 固定基线 `1e2ddfc0c65502776f226973eb49cf7ba02c67cb`，通过 `git archive` 导出到临时目录，与工作树共用未变更的依赖，使用相同隔离环境、原 5000ms 正文预算和单 worker 比较
- 定位前，四个纯后端失败文件、对应 Backend、协议、Vitest 配置、setup 与依赖锁文件和基线相同；UI 集成用例在 render 前已经真实执行状态查询、预览、采用。没有发现 D 收尾界面改动引起后端超时的证据
- 基线原 5 个失败文件共 **75 项全部通过，43.18 秒**；代表用例基线 662ms、当前修改前 650ms，先前同例曾耗时 4819ms。说明既有流程对运行条件敏感，不能据一次重跑通过宣称问题已解决
- 原 37 项失败发生时没有保留每个 syscall 的系统级追踪，无法事后证明最初一次越过 5000ms 的具体操作或归因于某个外部进程。本轮确认并修复的是可复现的重复扫描放大及超时后的清理竞态，不把磁盘故障、CLI 或本轮 UI 写成已确认原因

### 已确认的开销与修复

1. `SkillSyncService.state()` 原先独立执行 inventory、listDeployments，再为每个部署或可采用观察重新执行 syncLocation；每次 location 又发现目标并完整扫描库存。8 个外部技能的一次状态查询发现 targets **10 次**，两个并发状态查询共 **6 次**，新增回归在修复前明确失败
2. 新增仅供一次只读状态聚合使用的 `readSyncState()`：targets/inventory 在本次请求内复用，严格归属读取保留惰性和错误处理；下一次或并发请求各自重新读取，不增加全局缓存、缓存有效期或协议字段
3. 每个 location 的当前内容 hash、恢复日志和 reservation 校验仍实时执行；prepare、apply、写前/暂存后复核、锁、物理路径身份与归属验证仍走原来的 fresh 方法，所有文件和目录 fsync 不变
4. 原测试正文超时不会取消已经执行的异步代码；afterEach 却先恢复故障注入 mock 并递归删除目录，导致事务继续写入、出现 `ENOTEMPTY` 并干扰后续测试。清理必须等待整段测试正文及已发出的 UI 请求结束，而不只等待某一个内层 request；超时仍如实失败，不增加正文或 hook 预算
